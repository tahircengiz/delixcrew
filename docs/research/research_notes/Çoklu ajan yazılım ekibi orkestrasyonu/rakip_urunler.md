## Soru 1 — Görev alımı ve planlama: onaylanacak plan/spec üretiliyor mu? Görev boyutlandırma ve ayrıştırma; ürün içi rol uzmanlaşması (architect / implementer / reviewer / tester)

### Takeaway
2026 sonunda sektör iki kampa ayrılmış durumda: (a) **spec/plan kapısı zorunlu veya varsayılan** (Kiro üç dosyalı spec + faz onayı, Jules "plan → approve → code", Factory Specification Mode, Antigravity Implementation Plan artifact'i + review policy, Roo Orchestrator'da her alt görev için onay) ve (b) **plan isteğe bağlı/güven temelli** (Devin 2.1 "yalnız emin değilse durur", Codex cloud ve Copilot coding agent doğrudan PR'a gider). Rol uzmanlaşması çoğunlukla "mode" (Roo Architect/Code/Debug, Cline Plan/Act, Aider Architect/Editor) ya da "subagent/custom droid" düzeyinde; tam bir architect→implementer→reviewer→tester hattını ürün içinde adlandırılmış rollerle kuran tek ticari örnek yok, en yakını Kiro'nun spec fazları ve Devin'in "Devin Review + kendi bulgularını düzeltme" döngüsü.

### Inferences
- Plan kapısının yeri ürünün hedef kitlesine göre kayıyor: IDE/CLI araçları (Kiro, Factory, Cline, Roo) insan hemen yanında olduğu için senkron onay istiyor; asenkron "PR fabrikaları" (Codex cloud, Copilot agent, Jules dışında) onayı PR'a erteliyor. Devin 2.1'in "confidence-gated" yaklaşımı ikisinin arasında bir üçüncü yol.

- Kiro'nun "Quick Spec without approval gates" ve Devin'in "yalnız emin değilse dur" tasarımları, onay kapısının sabit değil **göreve ve güvene göre ölçeklenen** bir parametre olarak ele alındığını gösteriyor.

## Soru 2 — İzolasyon ve handoff: görev başına sandbox/VM/worktree, branch ve PR kuralları, bağlamın ajana verilme biçimi (Knowledge/Playbooks, AGENTS.md, Copilot instructions, Cursor rules)

### Takeaway
Hosted ürünlerin hepsi görev başına atılabilir izole ortam kullanıyor (Devin VM/snapshot, Codex workspace, Copilot "ephemeral, firewalled environment", Cursor Firecracker microVM, Jules Cloud VM, OpenHands sandbox); hepsi ayrı branch'e push + PR ile teslim ediyor. Bağlam aktarımı 2026'da **AGENTS.md etrafında fiilen standartlaştı** (Codex, Copilot, Jules, OpenHands, Factory, Cursor hooks dışında) ve üstüne üretici-özel katmanlar (Devin Skills/Knowledge, Copilot `copilot-instructions.md` + `*.instructions.md` + `excludeAgent`, Cursor `environment.json`/`hooks.json`, Kiro `.kiro/hooks` + steering) biniyor.

### Cited Findings

**Devin**
- Managed Devins: büyük görev iş paketlerine bölünür, her paket "kendi izole VM'inde" çalışan bir managed Devin'e verilir; koordinatör oturum ilerlemeyi izler (vendor claim, tarihsiz) — [Devin Docs, Advanced Capabilities](https://docs.devin.ai/work-with-devin/advanced-capabilities)

- Knowledge: organization/enterprise "environment blueprint"lerinde tanımlı Knowledge oturumlara ulaşır (2026-09-23); child session parent'ın özetiyle başlar (2026-09-25) — aynı kaynak.

**GitHub Copilot coding agent**
- "The cloud agent runs in an ephemeral, firewalled environment with automated security scanning"; "The environment is destroyed after the session ends, ensuring that no state persists between runs"; branch: "It can only push to a single branch: the existing pull request branch when triggered via @copilot ... or otherwise to a new copilot/ branch"; "The agent does not have access to Actions organization or repository secrets"; "Each commit message includes a link to the agent session logs"; görevi başlatan insan commit'te co-author (tarihsiz) — [GitHub Docs, Responsible use of coding agent](https://docs.github.com/en/copilot/responsible-use/copilot-coding-agent)

### Inferences
- "Branch per task + PR + ortam yok edilir" artık masa bedeli; farklılaşma **ortam tanımının kaynak kontrolünde olması** (Cursor `environment.json`, Codex install script, Devin blueprint/snapshot) ve **ağ egress politikası** (Copilot firewall varsayılan açık, Cursor domain allowlist, Codex domain listesi) üzerinde.
- Copilot'un "talimatı head branch'ten oku" (2026-07) ve Codex'in "en yakın AGENTS.md kazanır" kuralı, bağlam dosyalarını kodla birlikte sürümlenen, PR ile test edilebilen artefakt sayma yönünde birleşiyor; Devin'in Knowledge/Playbook'u Skills'e (repo'daki `SKILL.md`) taşıması (2026-09/10) aynı eğilimi doğruluyor: üretici-özel bulut veritabanından repo içi dosyaya kayış.
- Devin child session'ın "parent özetiyle başlaması" ve Roo'nun "yalnız özet parent'a döner" kuralı, çok ajanlı akışta bağlam aktarımının bilinçli olarak **özet-aracılı ve tek yönlü** tutulduğunu gösteriyor (context poisoning ve maliyet).

### Inferences
- Dört büyük olayın hiçbirinde "model hallucinated" birincil neden değil; hepsinde (a) uzun ömürlü/geniş token, (b) güvenilmeyen girdinin (branch adı, PR'la gelen workflow, npm paketi) ayrıcalıklı yürütmeye ulaşması, (c) izin kapılarını bayrakla kapatma imkânı var. Ekip orkestrasyonu için çıkarım: onay kapısı **ajan içinde** değil, ajanın kapatamayacağı **altyapıda** (ağ egress, kısa ömürlü token, Actions onayı, branch protection) olmalı.
- Üretici yanıtlarının ortak çizgisi (firewall varsayılan açık, secret'a erişim yok, oturum log linki, co-author) "denetlenebilirlik + egress kontrolü"; plan onayı değil. Yani güvenlik dersi review kapısına değil izolasyona yazılmış.
- Ekonomik çalışmalar + AIDev "abandoned %38" bulgusu birlikte, darboğazın üretim değil **insan review kapasitesi** olduğunu gösteriyor; üreticiler bunu ajan-review (Devin Review, Codex review, Copilot code review) ile telafi etmeye çalışıyor, bağımsız veri bunun merge oranını mı yoksa yalnız self-merge oranını mı artırdığını henüz ayırt edemiyor.
