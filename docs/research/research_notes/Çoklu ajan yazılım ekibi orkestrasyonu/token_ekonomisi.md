# Çoklu ajan AI kodlama kurulumlarında token ekonomisi ve derinliği kaybetmeden maliyet kontrolü (Kasım 2026)

> Araştırma tarihi: 2026-11-01. Fiyatlar `platform.claude.com/docs/en/about-claude/pricing` sayfasından aynı gün çekildi. "Topluluk" ya da "anekdot" etiketli sayılar kontrollü ölçüm değildir. Alıntılar kaynak dilinde (İngilizce) bırakıldı.

## Soru 1 — Yayınlanmış ölçümler: çoklu ajan tek ajana göre ne kadar pahalı, ortalama geliştirici maliyeti nedir?

### Takeaway
Anthropic'in kendi ölçümleri ajanların sohbetin ~4 katı, çoklu ajan sistemlerinin ~15 katı token kullandığını; Claude Code agent teams'in plan modunda ~7 kat token yaktığını söylüyor. Bağımsız kontrollü ölçümler (Vals AI, Ekim 2026) kodlamada ekibin tek ajana göre 1.8–5.1 kat pahalı olduğunu ve dört karşılaştırmadan yalnız birinde istatistiksel olarak anlamlı kalite kazancı sağladığını gösteriyor; ortalama Claude Code maliyeti kurumsal dağıtımlarda ~13 $/geliştirici/aktif gün.

### Cited Findings
- "agents typically use about 4× more tokens than chat interactions, and multi-agent systems use about 15× more tokens than chats." — [Anthropic Engineering, How we built our multi-agent research system (Haziran 2025)](https://www.anthropic.com/engineering/multi-agent-research-system)
- Aynı yazı: "token usage by itself explains 80% of the variance" (BrowseComp performansında); üç faktör (token, tool call sayısı, model seçimi) %95'ini açıklıyor; "upgrading to Claude Sonnet 4 is a larger performance gain than doubling the token budget on Claude Sonnet 3.7." — [Anthropic Engineering](https://www.anthropic.com/engineering/multi-agent-research-system)
- Aynı yazı: Opus 4 lider + Sonnet 4 subagent kurulumu "outperformed single-agent Claude Opus 4 by 90.2% on our internal research eval"; araştırma süresi karmaşık sorgularda %90'a kadar kısaldı. — [Anthropic Engineering](https://www.anthropic.com/engineering/multi-agent-research-system)
- Aynı yazı, ekonomik koşul: "multi-agent systems require tasks where the value of the task is high enough to pay for the increased performance"; kodlama için uyarı: "most coding tasks involve fewer truly parallelizable tasks than research." — [Anthropic Engineering](https://www.anthropic.com/engineering/multi-agent-research-system)
- Claude Code maliyet dokümanı (2026-11-01'de okunan sürüm): "the average cost is around $13 per developer per active day and $150-250 per developer per month, with costs remaining below $30 per active day for 90% of users." — [Claude Code docs, Manage costs](https://code.claude.com/docs/en/costs)
- Aynı doküman: "Agent teams use approximately 7x more tokens than standard sessions when teammates run in plan mode, because each teammate maintains its own context window and runs as a separate Claude instance." — [Claude Code docs, Manage costs](https://code.claude.com/docs/en/costs)
- Agent teams dokümanı: "Token costs scale linearly: each teammate has its own context window and consumes tokens independently"; subagent vs team tablosunda token cost "Lower: results summarized back to main context" vs "Higher: each teammate is a separate Claude instance". — [Claude Code docs, Agent teams](https://code.claude.com/docs/en/agent-teams)
- Vals AI Vibe Code Bench (50 full-stack web uygulaması, 2026-10-09, her kurulum bir kez çalıştırıldı): Claude Opus 5.5 medium effort tek ajan %91.5 / 4.08 $/uygulama / 20.3 dk; ekip %91.2 / 9.10 $ / 26.6 dk (2.2x maliyet, −0.3 puan). Opus 5.5 max effort tek ajan %89.8 / 23.77 $ / 74.7 dk; ekip %93.2 / 122 $ / 174.1 dk (5.1x maliyet, +3.4 puan, anlamlı değil). GPT 6 Sol medium tek %77.6 / 1.22 $; ekip %84.9 / 3.07 $ (2.5x, +7.3 puan, p=0.005 — tek anlamlı fark). GPT 6 Sol max tek %89 / 4.82 $; ekip %90.4 / 8.54 $ (1.8x). — [Vals AI, Multi-agent Vibe Code Bench](https://www.vals.ai/blogs/multi-agent-vibe-code-bench)
- Vals AI, fazla maliyetin kaynağı: "Most of the extra spend is cached input." Opus max effort'ta subagent'lar uygulama başına medyan 224 M cached token okudu; lider 17 M, tek ajan 55 M. "The extra time was subagent work, not idle time, and longer runs did not score higher." Yazarların uyarısı: "These observations come from one benchmark of full-stack web apps and may not carry over to other kinds of work." / "Neither option was a clear default." — [Vals AI](https://www.vals.ai/blogs/multi-agent-vibe-code-bench)
- Kontrollü akademik çalışma (arXiv 2609.04217, Haziran 2026, 7B donmuş omurga, ALFWorld/WebShop): Planner-Executor-Critic ekibi tek ajana göre "not statistically better ... 0.769 versus 0.754, p = 0.80, despite using 1.8 times more evaluation calls"; "With 2-3 times free compute, the team only matches the single agent"; "Under equal inference cost, multi-agent structure adds cost without clear benefit." Kazancın tamamı executor'dan geliyor. — [arXiv 2609.04217](https://arxiv.org/abs/2609.04217)
- Tokenomics (Concordia, Ocak 2026, ChatDev + GPT-5 reasoning, 30 görev): Code Review aşaması tokenların ortalama %59.4'ünü tüketiyor; input tokenlar ortalama %53.9 ile en büyük pay; ana maliyet "automated refinement and verification rather than initial code generation". — [arXiv 2601.14470](https://arxiv.org/abs/2601.14470)
- AgentTaxo (ICLR 2025 Workshop, Wang vd.): LLM çoklu ajan sistemleri "significantly higher inference latency and token costs due to repeated LLM calls"; ajanlar arası iletişimde "redundant reasoning results that are often reused for validation" tespit ediliyor (nicel oran abstract'ta yok). — [ICML/ICLR sayfası](https://icml.cc/virtual/2025/49320)
- Topluluk/anekdot — Quesma (Jacek Migdal, 2026-08-11): abonelikle yapılan işin API liste fiyatı karşılığı: yazar Max 5x 100 $ → 2.092 $ (21x); Max 20x 200 $ → 2.986 $ (15x); Simon Willison Max 5x → ~1.200 $ (12x); SemiAnalysis testi Max 20x → ~8.000 $ (40x); HN aralığı 12–50x. Liste fiyatı tahminidir, gerçek fatura değil. — [Quesma blog](https://quesma.com/blog/claude-code-pricing-for-enterprise/)
- Topluluk/anekdot — aynı Quesma yazısı, tek 24 saatlik oturum: 180.91 $ liste fiyatı; bağlam 72k → 504k token; tek bir skill yüklemesi ~326k cached token (6.65 $); compaction 424k → 71k ve 504k → 56k; 65/117/489 dakikalık aralardan sonra 1 saatlik cache düşüp 93k/201k/51k token yeniden yazıldı (1.87 $/4.02 $/1.01 $); tüm oturumlarda maliyetin %82'si cache ile ilgili. — [Quesma blog](https://quesma.com/blog/claude-code-pricing-for-enterprise/)
- Topluluk tahmini (ölçüm değil) — CloudZero aracılığıyla Developers Digest (2026-07-31): 1 oturum ~13 $/gün; 3 paralel ajan 30–40 $/gün; 5–10 ajan 50–130 $/gün; "Opus 4.7 orchestrator with four Sonnet 4.6 workers costs about 40% less than five Opus agents" (varsayım tabanlı hesap). — [Developers Digest](https://www.developersdigest.tech/blog/what-parallel-claude-agents-actually-cost)

### Inferences
- Üç bağımsız ölçüm (Anthropic 15x araştırma, Vals 1.8–5.1x kodlama, arXiv 1.8x eşit bütçe) birbirini destekliyor: kodlamada çoklu ajan primi tipik olarak 2–5 kat; araştırma gibi yüksek paralellikli işlerde 15 kata çıkıyor.
- Vals verisi "fazla maliyet = subagent'ların kendi bağlamlarını her çağrıda yeniden okuması" diyor; Opus 5.5'te 224 M cached read × 0.20 $/M ≈ 45 $/uygulama yalnız subagent cache read'i. Yani ekibin faturası çıktı değil, tekrar okunan girdi.
- Vals'te Opus 5.5 medium tek ajanın (4.08 $) Opus max ekibin (122 $) %98'ini vermesi: "daha fazla ajan" yerine "daha az effort, tek ajan" çoğu uygulama inşası işinde baskın strateji.

### Gaps
- Anthropic'in 15x ve 7x rakamları dışında Claude Code'a özgü, Anthropic tarafından yayımlanmış subagent/agent team maliyet ölçümü bulunamadı.
- Aramada geçen "UIUC, 7 veri seti, 4–220x token" iddiasının birincil kaynağı bulunamadı; alıntılanmamalı.
- Vals çalışması her kurulumu bir kez koşturdu; varyans uygulamalar arası, koşular arası değil.

### Inferences
- Fiyat merdiveni (input/output): Fable 5.1 = 2.5× Opus 5.5 = 5× Sonnet 5.5 = 100× Haiku 5.5 (≤100K). Cache read'de merdiven düzleşiyor: Fable 0.25 / Opus 0.20 / Sonnet 0.10 / Haiku 0.01. Bu yüzden uzun, cache'lenmiş orkestratör bağlamında Fable→Opus düşüşü çok az tasarruf eder; tasarruf çıktıda ve ilk okumada.
- Haiku 5.5'in >100K promptlarda 5× pahalılaşması, "arama/özet subagent'ı Haiku" stratejisinde subagent bağlamını 100K altında tutmayı (kısa `maxTurns`, hedefli prompt) zorunlu kılar.
- Anthropic'in resmi rol tavsiyesi üç katmanlı: orkestratör/plan = Opus (gerekirse Fable), uygulayıcı/teammate = Sonnet, arama/özet/compaction = Haiku. "Reviewer" rolü için ayrı bir resmi öneri yok; Vals/Tokenomics bulguları review'ın en pahalı aşama olduğunu söylüyor.

### Gaps
- Fiyat sayfasında max output token ve bağlam penceresi yer almıyor; 1M/128K değerleri Claude Code docs ve yerel skill tablosundan.
- Max planının haftalık Opus saat/mesaj sayısı için resmi rakam bulunamadı (support makalesi 404 verdi); üçüncü taraf tablolar birbiriyle çelişiyor.
- Küçük modelin code review'da yeterli olduğuna dair benchmark kanıtı bulunamadı; Haiku 5.5 duyurusu review'dan söz etmiyor.

## Soru 3 — Tokenlar nereye gidiyor? (bağlam yeniden okuma, subagent başlangıcı, CLAUDE.md/system prompt tekrarı, tool çıktısı)

### Takeaway
Claude Code her istekte tüm konuşmayı yeniden gönderir; tipik görevde token olarak en büyük kalem cache read (örnek: 2.0M cache read / 200K yeni input / 60K output), maliyet olarak en büyük kalem output. Subagent'lar kendi bağlamlarını her çağrıda yeniden okur ve çoklu ajanda fazla harcamanın çoğu budur; her subagent/teammate CLAUDE.md, MCP ve skill'leri sıfırdan yükler.

### Cited Findings
- "Claude Code sends your full conversation with every request, and each time Claude uses tools it sends another request carrying that batch of tool results ... a one-line question in a session that has been open all day still draws usage for the whole conversation." — [Manage costs](https://code.claude.com/docs/en/costs)
- Örnek oturum (Opus 5 fiyatı): 2.0M cache read 1.00 $, 200K fresh input 1.00 $, 60K output 1.50 $ = 3.50 $; "Cache reads are the biggest line by tokens, at 2M." / "Output is the smallest by tokens and the biggest by cost." / "On Opus 5.5 an output token costs 100 times a cache read." Hesap makinesi ön ayarı: input'un %91'i cache'ten. — [Osmani, What a task costs on Opus 5.5](https://claude.dev/blog/what-a-task-costs-on-opus-5-5/)
- Tur başına bağlam büyümesi: 20K bağlamda okuma ~0.004 $, 30 tur ≈ 0.12 $; 150K bağlamda ~0.03 $/okuma, 30 tur ≈ 0.90 $ yalnız okumalar; 40 tur × 70K ≈ 2.8M input, %90 cache ile 1.62 $, %96 ile 0.99 $, cache'siz 11.20 $. "No other setting moves input cost this much." — [Osmani](https://claude.dev/blog/what-a-task-costs-on-opus-5-5/)
- Cache write vs read (120K bağlam, Opus 5.5): 5 dk write ~0.60 $, read ~0.02 $ — "One write costs as much as 25 reads"; 1 saat write ~0.96 $. — [Osmani](https://claude.dev/blog/what-a-task-costs-on-opus-5-5/)
- Thinking: "Thinking tokens are billed as output tokens, and the default budget can be tens of thousands of tokens per request depending on the model." Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable'da thinking kapatılamaz; `/effort` ile düşürülür. — [Manage costs](https://code.claude.com/docs/en/costs); "high adds 20K thinking tokens across a task. On Opus 5.5 that's $0.40." — [Osmani](https://claude.dev/blog/what-a-task-costs-on-opus-5-5/)
- Subagent başlangıç bağlamı: "Each subagent starts with a fresh, isolated context window." Başlangıç bağlamı system prompt, görev mesajı, CLAUDE.md dosyaları, git status snapshot'ı, preloaded skill'ler ve sibling roster'ı içerir. Subagent açıklamaları her oturumda bağlamda yer alır; toplam 15.000 token üstünde başlangıç uyarısı. Sonuçlar ana bağlama döner: "Running many subagents that each return detailed results can consume significant context, and each subagent spends tokens of its own while it runs." — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Teammate başlangıcı: "When spawned, a teammate loads the same project context as a regular session: CLAUDE.md, MCP servers, and skills ... The lead's conversation history does not carry over." / "Keep spawn prompts focused. Teammates load CLAUDE.md, MCP servers, and skills automatically, but everything in the spawn prompt adds to their context from the start." / "Each active teammate continues consuming tokens until it exits or the session ends." — [Agent teams](https://code.claude.com/docs/en/agent-teams), [Manage costs](https://code.claude.com/docs/en/costs)
- Subagent cache'i ebeveynden ayrı: "Its first request doesn't read the parent's cache, because the two prefixes differ, and it warms a cache of its own across its turns." Fork ise ebeveynin prefix'ini okur. — [Claude Code docs, Prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Vals: Opus max ekipte subagent'lar medyan 224M cached token/uygulama okudu (lider 17M, tek ajan 55M); "Most of the extra spend is cached input." — [Vals AI](https://www.vals.ai/blogs/multi-agent-vibe-code-bench)
- CLAUDE.md: "loaded into context at session start ... those tokens are present even when you're doing unrelated work." / "Aim to keep CLAUDE.md under 200 lines". `/usage` öneri örneği: "25%  Trim ~/code/api/CLAUDE.md · 49k tokens per request". — [Manage costs](https://code.claude.com/docs/en/costs)
- Tool çıktısı: "Instead of Claude reading a 10,000-line log file to find errors, a hook can grep for `ERROR` and return only matching lines, reducing context from tens of thousands of tokens to hundreds." MCP tool tanımları varsayılan olarak deferred; CLI araçları (gh, aws) MCP'den daha bağlam-verimli. — [Manage costs](https://code.claude.com/docs/en/costs)
- Arka plan tüketimi: session recap, idle compaction, prompt suggestions (cache read ağırlıklı), session-scoped scheduled tasks (her tetiklemede tüm bağlam), cross-session messages, goal check-in'leri (goal başına en fazla 3), subagent/workflow istekleri, compaction'ın kendisi ("`/compact` reads the conversation it summarizes"). — [Manage costs](https://code.claude.com/docs/en/costs)
- Topluluk: tek skill yüklemesi ~326k cached token (6.65 $); bağlam 72k→504k. — [Quesma](https://quesma.com/blog/claude-code-pricing-for-enterprise/)
- Akademik: ChatDev tarzı MAS'ta Code Review aşaması tokenların %59.4'ü, input %53.9. — [arXiv 2601.14470](https://arxiv.org/abs/2601.14470)

### Inferences
- Tek ajanda maliyetin yaklaşık yarısı output (thinking dahil), kalanı cache read + ilk okuma. Çoklu ajanda denge kayıyor: N subagent × kendi bağlamı × tur sayısı → cache read toplamı baskın kalem oluyor (Vals: 224M read).
- Her subagent CLAUDE.md + git status + skill'leri yüklediği için 49k token'lık bir CLAUDE.md, 10 subagent'lı bir fan-out'ta yarım milyon token "sabit gider" üretir; `omitClaudeMd` ve Explore/Plan'ın CLAUDE.md'siz başlaması bu gideri sıfırlar.
- Çoklu ajanda "review/verification" aşamasının token payı (%59) tek ajandaki "kod yazma" payını geçiyor; reviewer rolünün model ve tur bütçesi en büyük kaldıraç.

### Gaps
- Claude Code'un system prompt + tool tanımlarının token boyutu resmi olarak yayımlanmamış; `/context` komutuyla oturum içinde görülebilir.
- Subagent başlangıcının (spin-up) sabit token maliyeti için resmi rakam yok.

## Soru 4 — Model katmanlama stratejileri ve ölçülmüş trade-off'ları (routing/cascade kanıtı)

### Takeaway
Anthropic Claude Code'da "Opus lider / Sonnet teammate / Haiku subagent" katmanlamasını öneriyor ama ölçülmüş kalite kaybı rakamı yayımlamıyor. Routing literatürü (RouteLLM, 2024) GPT-4 kalitesinin %95'ini koruyarak MT Bench'te %85, MMLU'da %45 maliyet düşüşü gösteriyor; Anthropic'in kendi tavsiyesi ise cascade kurmadan önce "aynı güçlü model, daha düşük effort" alternatifini ölçmek, çünkü cache model kapsamlı.

### Cited Findings
- RouteLLM (LMSYS, 2024-07-01): GPT-4 Turbo ↔ Mixtral 8x7B arasında yönlendirme, GPT-4'ün %95 performansını korurken "cost reductions of over 85% on MT Bench, 45% on MMLU, and 35% on GSM8K"; MT Bench'te matrix factorization router %26 GPT-4 çağrısı (rastgele baz çizgisine göre %48 ucuz), LLM-judge ile zenginleştirilmiş veriyle %14 çağrı; MMLU'da %54 GPT-4 çağrısı. Claude 3 Opus / Llama 3 8B çiftine yeniden eğitimsiz "performance comparable". — [LMSYS blog](https://lmsys.org/blog/2024-07-01-routellm/); [arXiv 2406.18665](https://arxiv.org/abs/2406.18665v4)
- Routing eleştirisi (pratisyen): maliyet odaklı routing "treats all quality degradation as equal, when in practice the queries you're downgrading are disproportionately the ones where quality matters most." — [tianpan.co, Quality-Aware Model Routing (2026-04-14)](https://tianpan.co/blog/2026-04-14-quality-aware-model-routing)
- Anthropic araştırma sistemi: model yükseltmesi token bütçesini ikiye katlamaktan daha değerli ("upgrading to Claude Sonnet 4 is a larger performance gain than doubling the token budget on Claude Sonnet 3.7"). — [Anthropic Engineering](https://www.anthropic.com/engineering/multi-agent-research-system)
- Vals AI: Opus 5.5'te medium→max effort tek ajanda anlamlı kazanç yok (p=0.48) ama maliyet 4.08 $ → 23.77 $ (5.8x); GPT 6 Sol'da max effort tek ajanı +11.4 puan yükseltti (p<0.001). "Higher effort was an alternative worth weighing." — [Vals AI](https://www.vals.ai/blogs/multi-agent-vibe-code-bench)
- Model geçişinin cache maliyeti: "if you're 100k tokens into a conversation with Opus and want to ask a question that is fairly easy to answer, it would actually be more expensive to switch to Haiku than to have Opus answer, because we would need to rebuild the prompt cache for Haiku." Çözüm: subagent + hand-off mesajı. — [Shihipar, Prompt caching is everything](https://claude.dev/blog/lessons-from-building-claude-code-prompt-caching-is-everything/)
- Claude Code docs: "each model has its own cache. Switching models recomputes the entire request even when the content is identical"; `opusplan` her plan-mode geçişinde cache'i sıfırlar; skill frontmatter'ındaki farklı `model` de o tur için model geçişi sayılır. — [Prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Opus 5 → Opus 5.5 geçişi, destek bileti benchmark'ı (44 bilet): "The move to Opus 5.5, at low effort, cut the benchmark's cost by about 18%. Running prompt-audit cut it by a further 9%, to about 25% below the Opus 4.8 starting point." Fiyattan gelen oturum tasarrufu %31; aboneliklerde limitler "about 25% further". — [Osmani](https://claude.dev/blog/what-a-task-costs-on-opus-5-5/)
- Haiku 5.5 subagent rolü için Anthropic'in resmi konumu (yukarıda): subagent, summarization, compaction, classification. — [Anthropic, Claude Haiku 5.5](https://www.anthropic.com/news/claude-haiku-5-5)
- Topluluk tahmini: Opus orkestratör + 4 Sonnet işçi, 5 Opus'a göre ~%40 ucuz (CloudZero hesabı, ölçüm değil). — [Developers Digest](https://www.developersdigest.tech/blog/what-parallel-claude-agents-actually-cost)
- Yerel referans (claude-api skill, cost-optimization bölümü, URL yok): "lower effort on the newest models often matches or exceeds prior-generation performance at high effort"; "Judge cost per completed task, not per request - a cheaper request that needs more turns or retries to finish the job isn't cheaper." Resmi sayfadan doğrulanmadı.

### Inferences
- Routing kanıtı (RouteLLM) sohbet/benchmark sorgularından; uzun bağlamlı agentic kodlamaya doğrudan taşınmaz; Claude Code içinde fiili routing mekanizması "subagent'a model atamak"tır, oturum içi `/model` değil.
- Kasım 2026 fiyatlarıyla katmanlama kazancı: 5 Opus 5.5 yerine 1 Opus 5.5 + 3 Sonnet 5.5 + 1 Haiku 5.5 kabaca (4+2·3+0.1)/(4·5) ≈ %50 daha ucuz input'ta; Haiku'nun >100K bağlamda 5x'e çıkması ve Sonnet'in Opus'un yarısı olması nedeniyle gerçek kazanç subagent bağlam boyutuna bağlı.
- Kalite riski en çok "reviewer"da: review en pahalı aşama (Tokenomics %59) ama küçük modelin review yeterliliğine dair ölçüm yok; güvenli sıra: önce effort düşür (Vals: Opus medium ≈ max), sonra model düşür.

### Gaps
- Anthropic'in Haiku/Sonnet subagent kalitesi için yayımlanmış A/B ölçümü yok.
- 2025–2026 cascade/routing makalelerinden agentic kodlamaya özgü, Claude 5 ailesiyle yapılmış bir ölçüm bulunamadı.

## Soru 5 — Bağlam hijyeni teknikleri ve ölçülmüş etkileri (caching, TTL, özet-dönüş, maxTurns, autoCompactWindow, compaction, oturum başına tek iş, repo haritası, tool çıktısı kısıtlama)

### Takeaway
En büyük kaldıraç prompt cache hit oranı (aynı 2.8M input: %90 hit 1.62 $, %96 hit 0.99 $, cache'siz 11.20 $). İkinci: bağlamı küçük tutmak (subagent özet-dönüşü 1.000–2.000 token; `/clear`; 150K'da compaction ~0.25 $ ve ~10 turda amorti). Üçüncü: subagent başlangıç yükünü kesmek (`omitClaudeMd`, Explore/Plan CLAUDE.md'siz, kısa description, `maxTurns`).

### Cited Findings
**Prompt caching ve TTL**
- Cache katmanları: system prompt + tool tanımları → proje bağlamı (CLAUDE.md, auto memory, rules) → konuşma. "A change to the system prompt invalidates everything." Cache'i bozan eylemler: model değiştirme, effort değiştirme (Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.1'de API key veya abonelikte korunur), fast mode açma, MCP sunucusu ekleme/çıkarma (tool search deferred ise korunur), plugin aç/kapa (yalnız MCP sağlayanlar), tüm bir tool'u deny etmek, compaction, çok sayıda görsel biriktirme, Claude Code yükseltmesi. Koruyanlar: dosya düzenleme, CLAUDE.md'yi oturum içinde düzenleme (ama uygulanmaz), permission mode, output style, skill/komut çağırma, `/recap`, `/rewind`, subagent spawn. — [Prompt caching](https://code.claude.com/docs/en/prompt-caching)
- TTL kovaları: ana konuşma abonelikte plan limiti içinde 1 saat; usage credits / API key / cloud'da 5 dk; "Everything else" (subagent, workflow, in-process teammate, fork, compaction, session title) her durumda 5 dk. Ayar: `promptCacheTtl` / `CLAUDE_CODE_PROMPT_CACHE_TTL` (ana), `subagentPromptCacheTtl` / `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` (diğerleri); `ENABLE_PROMPT_CACHING_1H=1`, `FORCE_PROMPT_CACHING_5M=1`; v2.1.242+. 1 saatlik TTL "costs more on short bursts of work that never idle past five minutes". — [Prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Cache kapsamı: makine + dizine bağlı; aynı dizinde paralel oturumlar birbirinin cache'ini okuyabilir. `/usage` içinde `Prompt cache (main)` satırı (v2.1.251+): örnek "14 requests · 91% of input tokens from cache · 2 misses ... warm (1h TTL)"; `likely cause: tool definitions changed` (v2.1.260+). — [Prompt caching](https://code.claude.com/docs/en/prompt-caching); [Manage costs](https://code.claude.com/docs/en/costs)
- Anthropic tasarım ilkesi: "At Claude Code, we build our entire harness around prompt caching ... we run alerts on our prompt cache hit rate and declare SEVs if they're too low." Plan mode'da tool'lar değiştirilmez (EnterPlanMode/ExitPlanMode tool), MCP tool'ları `defer_loading: true` stub olarak gönderilir, compaction ebeveynin prefix'ini paylaşan fork çağrısıyla "one tenth the price"a yapılır, özet "about 20k tokens". — [Shihipar](https://claude.dev/blog/lessons-from-building-claude-code-prompt-caching-is-everything/)
- Workflow fan-out'ta aynı prefix'li ajanlar ilk ajanın yanıtı başlayana kadar en fazla `CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS` (varsayılan 5000 ms) bekletilir ki ilk isteklerinde kardeşin cache'ini okusunlar. — [Workflows](https://code.claude.com/docs/en/workflows)

**Compaction / autoCompactWindow / clear**
- "A rough price for compacting at 150K tokens is about $0.25... Each later turn saves about $0.025 in reads, so the compaction pays for itself within about ten turns." Soğuk (cache süresi dolmuş) 150K bağlamda yeniden okuma yalnız input'ta ~0.75 $. — [Osmani](https://claude.dev/blog/what-a-task-costs-on-opus-5-5/)
- "A mid-session `/compact` then costs a fraction of what the context size suggests ... `/compact` costs the most when you resume an old session." Compaction yerine abandone edilmiş yol için `/rewind` (cache'lenmiş prefix'e döner). İdle compaction (`idleCompaction`, v2.1.290+). — [Prompt caching](https://code.claude.com/docs/en/prompt-caching)
- `autoCompactWindow`: `~/.claude/settings.json` içinde (ör. 200000), `/autocompact <size>`, `--autocompact 500k`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`; 100K–1M aralığı; Haiku 5.5'te varsayılan ~967K'da otomatik compaction. Subagent frontmatter'ında `autoCompactWindow` da var (in-process teammate'e uygulanır, v2.1.296+). — [Model configuration](https://code.claude.com/docs/en/model-config); [Agent teams](https://code.claude.com/docs/en/agent-teams)
- "Clear between tasks: Use `/clear` to start fresh when switching to unrelated work. Stale context wastes tokens on every subsequent message." "When you want a fresh start instead of continuity, `/clear` costs nothing." Özel compaction talimatı: `/compact Focus on code samples and API usage` ya da CLAUDE.md'de "# Compact instructions". — [Manage costs](https://code.claude.com/docs/en/costs)
- Anthropic context engineering (2025-09-29): compaction "architectural decisions, unresolved bugs, and implementation details" tutar, "redundant tool outputs" atar, "the five most recently accessed files" ile devam eder; tool result clearing "the safest lightest touch forms of compaction"; "context rot": "the model's ability to accurately recall information from that context decreases"; genel ilke "do the simplest thing that works". — [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Topluluk tahmini: `/clear` mesaj başına token maliyetini %30–50 düşürür (CloudZero, ölçüm yöntemi belirsiz). — [Developers Digest](https://www.developersdigest.tech/blog/what-parallel-claude-agents-actually-cost)

**Subagent özet-dönüşü, maxTurns, başlangıç yükü**
- "Subagents can use tens of thousands of tokens or more while exploring, but return a condensed, distilled summary of its work (often 1,000-2,000 tokens)." — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- "Delegate these to subagents so the verbose output stays in the subagent's context while only a summary returns to your main conversation. The subagent's own requests still draw on your usage." — [Manage costs](https://code.claude.com/docs/en/costs)
- `maxTurns` frontmatter: "Maximum number of agentic turns before the subagent stops ... Claude Code returns its output marked as partial, and Claude can resume it." `omitClaudeMd: true`: subagent CLAUDE.md'siz başlar; Explore ve Plan zaten CLAUDE.md ve git status'siz başlar "to keep research fast and inexpensive". Kısa description: 15.000 token toplamı üstünde uyarı. Eşzamanlı subagent limiti 20 (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`), derinlik 3 (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`). — [Subagents](https://code.claude.com/docs/en/sub-agents)
- `/btw`: bağlamdaki bir şey hakkında soru için, tool erişimsiz, geçmişe eklenmez. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Print modunda `--max-turns` ve `--max-budget-usd` (bkz. Soru 7). — [CLI reference](https://code.claude.com/docs/en/cli-reference)

**Handoff / not alma / repo haritası**
- Yapısal not alma: ajan "NOTES.md" ya da to-do dosyasına yazar, sonra yeniden yükler; Anthropic memory tool public beta. Not alma "iterative development with clear milestones" için uygun; compaction "extensive back-and-forth" için. — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Repo haritası / skill: "a 'codebase-overview' skill could describe your project's architecture, key directories, and naming conventions. When Claude invokes the skill, it gets this context immediately instead of spending tokens reading multiple files"; CLAUDE.md'den skill'e taşı ("Skills load on-demand only when invoked"). Code intelligence plugin'leri: "A single 'go to definition' call replaces what might otherwise be a grep followed by reading multiple candidate files." — [Manage costs](https://code.claude.com/docs/en/costs)
- Hook ile tool çıktısı filtreleme: PreToolUse hook test komutuna `| grep -A 5 -E '(FAIL|ERROR|error:)' | head -100` ekler; "tens of thousands of tokens to hundreds". — [Manage costs](https://code.claude.com/docs/en/costs)
- Spesifik prompt: "Vague requests like 'improve this codebase' trigger broad scanning"; plan mode ile yanlış yöne gidip yeniden çalışmayı önleme; `/rewind`; doğrulama hedefi vermek. — [Manage costs](https://code.claude.com/docs/en/costs)
- Model/effort'u oturum başında seç: "Pick your model and effort level at the top of a session, then save `/compact` for natural breaks between tasks." — [Prompt caching](https://code.claude.com/docs/en/prompt-caching)

### Inferences
- Etki sırası (büyükten küçüğe, kaynaklı rakamlara göre): (1) cache hit oranını %90+ tutmak (10x fark: 1.62 $ vs 11.20 $), (2) bağlamı küçük tutmak — `/clear`, oturum başına tek iş, 150K'yı geçmeden compaction, (3) subagent'a ağır işi verip 1–2K token özet almak, (4) subagent başlangıç yükünü kesmek (omitClaudeMd, kısa description, Haiku + maxTurns), (5) CLAUDE.md'yi 200 satır altında tutup ayrıntıyı skill'e taşımak, (6) tool çıktısını hook ile filtrelemek.
- "Oturum başına tek iş + STATUS.md handoff" tekniğinin doğrudan ölçümü yok; Anthropic'in "structured note-taking" ve "/clear costs nothing" ifadeleri ile Quesma'nın 504K bağlam örneği birlikte gerekçesini veriyor: uzun oturumda her tur tüm geçmişi cache'ten okur, 1 saatlik TTL kaçırılınca onlarca-yüz binlerce token yeniden yazılır.
- Subagent/teammate'ler varsayılan 5 dk TTL'de; uzun süren paralel işler için `subagentPromptCacheTtl: 1h` yazma ücretini 2x yapar ama 5 dk üstü beklemelerde tam yeniden okumayı önler — Vals'teki 224M cached read'in ne kadarının cache miss olduğu bilinmiyor.

### Gaps
- `omitClaudeMd`, `maxTurns`, hook filtrelemenin ölçülmüş dolar/token tasarrufu yayımlanmamış; yalnız nitel ("tens of thousands → hundreds").
- EGM tarzı dizin README'lerinin etkisi için kaynak bulunamadı; en yakın resmi öneri "codebase-overview skill".
- Claude Code'un genel cache hit oranı Anthropic tarafından açıklanmıyor; Quesma %82 "cache-related cost", Osmani %91 "read from cache" ön ayarı.

## Soru 6 — Çoklu ajan ne zaman değmez? Görev boyutuna göre katmanlama sezgileri

### Takeaway
Hem Anthropic hem bağımsız ölçümler aynı yerde buluşuyor: paralelleştirilemeyen, aynı dosyaya dokunan, çok bağımlılıklı ya da hızlı iteratif işlerde tek oturum hem ucuz hem en az o kadar iyi; çoklu ajan yalnız bağımsız parçalara bölünebilen, bir bağlam penceresini aşan ve değeri yüksek işlerde (geniş araştırma, çok dosyalı audit/migration, rakip hipotezlerle debugging) kendini ödüyor.

### Cited Findings
- Anthropic: "Simple fact-finding requires just 1 agent with 3-10 tool calls, direct comparisons might need 2-4 subagents with 10-15 calls each, and complex research might use more than 10 subagents"; erken hata modu "spawning 50 subagents for simple queries"; uygun olmayan alanlar "domains that require all agents to share the same context or involve many dependencies between agents"; "most coding tasks involve fewer truly parallelizable tasks than research". — [Anthropic Engineering](https://www.anthropic.com/engineering/multi-agent-research-system)
- Claude Code docs, ana konuşmada kal: "The task needs frequent back-and-forth or iterative refinement / Multiple phases share significant context, such as planning, implementation, and testing / You're making a quick, targeted change / Latency matters." Subagent kullan: "The task produces verbose output you don't need in your main context / You want to enforce specific tool restrictions / The work is self-contained and can return a summary." — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Agent teams: "For sequential tasks, same-file edits, or work with many dependencies, a single session or subagents are more effective." / "Start with 3-5 teammates for most workflows ... If you have 15 independent tasks, 3 teammates is a good starting point." / "Three focused teammates often outperform five scattered ones." / Görev boyutu: "Too small: coordination overhead exceeds the benefit; Too large: teammates work too long without check-ins". "For routine tasks, a single session is more cost-effective." — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- Workflow vs subagent vs team ölçek tablosu: subagent "A few delegated tasks per turn", agent teams "A handful of long-running peers", workflows "Dozens to hundreds of agents per run"; workflow'u "a task needs more agents than one conversation can coordinate" için kullan; önce küçük bir dilimde dene. — [Workflows](https://code.claude.com/docs/en/workflows)
- Vals AI: Opus 5.5'te ekip hiçbir effort seviyesinde anlamlı kazanç vermedi; tek anlamlı kazanç GPT 6 Sol medium'da. "Whether a team is worth it depends on the model, task, and budget." Gelecek iş: "tasks that split into independent parts that can proceed in parallel, such as large codebases or broad research." — [Vals AI](https://www.vals.ai/blogs/multi-agent-vibe-code-bench)
- Eşit bütçe çalışması: ekip 1.8x çağrı ile tek ajana eş; 2–3x bedava compute ile ancak eşitliyor. — [arXiv 2609.04217](https://arxiv.org/abs/2609.04217)
- Anthropic context engineering: multi-agent "complex research and analysis where parallel exploration pays dividends" için; genel ilke "do the simplest thing that works". — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Agent teams'in güçlü kullanım alanları: "Research and review", "New modules or features" (ayrı dosya sahipliği), "Debugging with competing hypotheses", "Cross-layer coordination". — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- Ultracode uyarısı: "each request uses more tokens and takes longer than the same request without a workflow ... reaches a session or weekly limit sooner." — [Workflows](https://code.claude.com/docs/en/workflows)

### Inferences
- Görev boyutuna göre kademe (kaynaklardan türetilmiş): (K0) tek dosya / hızlı değişiklik / iteratif → tek oturum, Sonnet veya Opus medium; (K1) tek iş ama gürültülü alt adımlar (test, log, doküman okuma) → ana oturum + Haiku/Sonnet subagent özet-dönüşlü; (K2) 3+ bağımsız dosya grubu ya da rakip hipotez → 3–5 teammate (Sonnet) + Opus lider, dosya sahipliği ayrık; (K3) onlarca-yüzlerce homojen birim (audit, migration) → workflow, `small/medium` size guideline, küçük dilimde ölçüm.
- Vals'teki en sağlam bulgu: "tek ajan, orta effort" baz çizgisini ölçmeden ekip kurmak, 2–5x maliyete karşılık ölçülemeyen kazanç satın almaktır.

### Gaps
- Görev büyüklüğü eşiklerini (ör. dosya sayısı, satır sayısı) maliyet/kaliteye bağlayan nicel bir çalışma bulunamadı; eşikler nitel öneri.

## Soru 7 — Guardrail'ler: bütçe kapları, kullanım uyarıları, izleme araçları, plan vs API rate limit

### Takeaway
Claude Code'da sert bütçe kapı yalnız print modunda (`--max-budget-usd`, subagent'lar dahil; `--max-turns`); etkileşimli modda uyarılar var: workflow "Large workflow" (>25 ajan ya da >1.5M projeksiyon token, yalnız bilgilendirici), subagent description >15K token, `/usage` içinde ≥%10 paylı öneriler. İzleme: `/usage`, status line, OpenTelemetry (`claude_code.cost.usage`, `token.usage` ile `query_source` main/subagent/auxiliary), ccusage (yerel JSONL, LiteLLM fiyatları). Kurumsal kap: Console workspace spend limit, Team/Enterprise usage credit limitleri, LiteLLM gateway.

### Cited Findings
- `--max-budget-usd`: "Stop the run once estimated spend on API calls reaches this amount (print mode only). Claude Code checks the cap against its client-side cost estimate, which can differ from your bill. Spend from subagents counts toward the cap. Spend can pass the cap, so leave headroom." `--max-turns`: "Limit the number of agentic turns (print mode only). Exits with an error when the limit is reached. No limit by default." `--autocompact <auto|tokens>` (v2.1.221+); `--effort low|medium|high|xhigh|max|ultracode`. — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- "Large workflow" uyarısı: "When a workflow schedules more than 25 agents, or its projected token total passes 1.5 million, its progress line ... shows a `Large workflow` warning ... The warning is advisory: it doesn't pause or limit the run." Size guideline eşiği değiştirir; ultracode açıkken uyarı gösterilmez. `workflowSizeGuideline`: `small` <5, `medium` <10 (varsayılan; Pro'da `small`), `large` <50, `unrestricted`. Sert sınırlar: 16 eşzamanlı ajan (`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` 1–256), 1.000 ajan/run, 4.096 öğe/`parallel()`. `/workflows` görünümü ajan başına token gösterir; `disableWorkflows` ile kapatılır. — [Workflows](https://code.claude.com/docs/en/workflows)
- Subagent limitleri: 20 eşzamanlı (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`), 3 katman derinlik; description toplamı >15.000 token → başlangıç uyarısı; `maxTurns` frontmatter. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- `/usage`: Session bloğu (liste fiyatıyla yerel hesap; `modelPricing` managed setting ile sözleşme fiyatı), `Prompt cache (main)` satırı, plan kullanım dağılımı: skill/subagent/plugin/MCP sunucusu başına yüzde; öneriler "at least 10%" paylı satırlar (ör. ### Inferences
- Etkileşimli Claude Code'da sert dolar kapı yok; otomasyon (CI, cron, Agent SDK) için `claude -p --max-budget-usd X --max-turns N` tek gerçek kap ve subagent'ları içeriyor. Etkileşimli oturumda "kap" = `maxTurns` frontmatter + eşzamanlı subagent limiti + `workflowSizeGuideline: small` + OTel alarmı.
- Abonelik planlarında maliyet dolara değil pencereye yansır; çoklu ajan (7x) haftalık limiti orantılı hızlı tüketir, bu yüzden Anthropic'in "Use Sonnet for teammates" tavsiyesi API'de dolar, abonelikte "limit süresi" tasarrufudur.
