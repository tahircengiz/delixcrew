## KQ1 — OWASP, NIST, Anthropic/OpenAI/Google/Microsoft: çoklu ajan sistemleri için güvenlik rehberi ve kodlama ekibine uygulanabilir somut önlemler

### Takeaway
2025–2026 rehberlerinin ortak çekirdeği üç ilkeye indirgenebilir: (1) ajanın okuduğu her şey (dosya, web, tool çıktısı, başka ajanın mesajı) **untrusted data**'dır ve komut değildir; (2) ajan yetkisi **statik least-privilege'ın ötesinde göreve göre dinamik** kısıtlanır (read-only reviewer, tool allowlist, kısa ömürlü token, sandbox); (3) geri alınamaz / yüksek etkili eylemler **model dışı deterministik bir politika motoru** ve insan onayıyla kapılanır, çünkü model-içi savunmalar (prompt, classifier) tek başına yetersizdir. OWASP Agentic Top 10 (Aralık 2025), Google (Mayıs 2025), Microsoft (Nisan 2025 / Haziran 2026), Meta "Rule of Two" (Ekim 2025) ve Anthropic'in Claude Code dokümanları bu noktada neredeyse kelimesi kelimesine örtüşür.

### Cited Findings

**OWASP Top 10 for Agentic Applications 2026 (ASI01–ASI10)**
- Aralık 9, 2025'te yayımlandı; "more than 100 industry experts, researchers, and practitioners" katkısıyla; OWASP LLM Top 10'un yerini almaz, onu genişletir — [OWASP GenAI](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026)
- On başlık: ASI01 Agent Goal Hijack, ASI02 Tool Misuse and Exploitation, ASI03 Identity and Privilege Abuse, ASI04 Agentic Supply Chain Vulnerabilities, ASI05 Unexpected Code Execution (RCE), ASI06 Memory & Context Poisoning, ASI07 Insecure Inter-Agent Communication, ASI08 Cascading Failures, ASI09 Human-Agent Trust Exploitation, ASI10 Rogue Agents — [AIGL özeti](https://www.aigl.blog/owasp-top-10-for-agentic-applications-2026.md); [Modulos özeti](https://docs.modulos.ai/frameworks/owasp-top-10-agentic)
- ASI01 önlemleri: "Treat all natural-language inputs as untrusted, including retrieved content and uploaded files"; yüksek etkili / hedef değiştiren eylemler için insan onayı; "Define and lock agent system prompts" — [Modulos özeti](https://docs.modulos.ai/frameworks/owasp-top-10-agentic)
- ASI02 (tool misuse) önlemleri: "per-tool least-privilege profiles (scopes, maximum rate, and egress allowlists)"; "fully qualified tool names and version pins" (alias çakışması / typosquat tool'a karşı); tool'ları izole sandbox'ta çalıştır; "Enforce outbound allowlists and deny all non-approved network destinations"; "delete, transfer, publish" için insan onayı — [Modulos özeti](https://docs.modulos.ai/frameworks/owasp-top-10-agentic)
- ASI03 (identity/privilege, confused deputy) önlemleri: "short-lived, narrowly scoped tokens per task"; "Run per-session sandboxes with separated permissions and memory, wiping state between tasks"; her ayrıcalıklı adımı merkezi policy engine ile yeniden doğrula — [Modulos özeti](https://docs.modulos.ai/frameworks/owasp-top-10-agentic)
- ASI04 (supply chain): "Sign and attest manifests, prompts, and tool definitions"; "Pin prompts, tools, and configs by content hash and commit ID"; imzasız bileşeni reddet; kill switch — [Modulos özeti](https://docs.modulos.ai/frameworks/owasp-top-10-agentic)
- ASI05 (kod çalıştırma — kodlama ajanı için en doğrudan madde): "Never run as root"; sandbox container, dosya sistemi erişimini çalışma dizinine kısıtla; "Separate code generation from execution with validation gates"; "Require human approval for elevated runs"; "Ban eval in production agents"; çalıştırmadan önce static scan — [Modulos özeti](https://docs.modulos.ai/frameworks/owasp-top-10-agentic)
- ASI06 (memory poisoning): "Scan all new memory writes"; oturum/alan bazlı segmentasyon; "Allow only authenticated, curated sources"; **ajanın kendi çıktısının otomatik olarak güvenilir belleğe geri yazılmasını engelle**; rollback/quarantine — [Modulos özeti](https://docs.modulos.ai/frameworks/owasp-top-10-agentic)
- ASI07 (inter-agent): "Use end-to-end encryption with per-agent credentials and mutual authentication"; mesajları imzala ve gizli/değiştirilmiş talimat için doğrula; "versioned, typed message schemas"; nonce/session id/timestamp — [Modulos özeti](https://docs.modulos.ai/frameworks/owasp-top-10-agentic)
- ASI08 (cascading): "Separate planning and execution via an external policy engine"; "quotas, progress caps, circuit breakers between planner and executor"; yüksek riskli çıktı aşağıya geçmeden insan incelemesi — [Modulos özeti](https://docs.modulos.ai/frameworks/owasp-top-10-agentic)
- ASI10 (rogue agents): "immutable and signed audit logs of all agent actions, tool calls, and inter-agent communication"; watchdog ajanlar; "Keys must never be directly available to agents" (orchestrator imzalamaya aracılık eder) — [Modulos özeti](https://docs.modulos.ai/frameworks/owasp-top-10-agentic)

**OWASP Top 10 for LLM Applications 2025 (LLM01, LLM06)**
- LLM01 Prompt Injection: direct (kullanıcı girdisi) ve indirect (web/dosya gibi dış içerik) ayrımı; önlemler: "Constrain model behavior", "Define and validate expected output formats", "Implement input and output filtering", "Enforce privilege control and least privilege access", "Require human approval for high-risk actions", "Segregate and identify external content", "Conduct adversarial testing and attack simulations"; sayfa açıkça "no fool-proof prevention is known" diyor — [OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)
- LLM06 Excessive Agency: üç kök neden — excessive functionality, excessive permissions, excessive autonomy. Önlemler: "Minimize extensions", "Minimize extension functionality", "Avoid open-ended extensions" (keyfi shell yerine dar araç; "a dedicated file-writing tool is safer than a general command runner"), "Minimize extension permissions", "Execute extensions in the user's context", "Require user approval", "Complete mediation" (yetkiyi LLM'e değil aşağı akış sisteme bırak), "Sanitise LLM inputs and outputs" (ASVS; SAST/DAST/IAST). Hasarı sınırlayan ama önlemeyen: logging/monitoring ve rate limiting — [OWASP LLM06](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/)

**NIST**
- SP 800-218A "Secure Software Development Practices for Generative AI and Dual-Use Foundation Models" SSDF (SP 800-218) üzerine community profile; 26 Temmuz 2024 final; EO 14110 direktifiyle hazırlandı — [NIST CSRC](https://csrc.nist.gov/pubs/sp/800/218/a/final)
- Kapsamı model üretim yaşam döngüsü (veri, eğitim, değerlendirme, entegrasyon); **ajan-ekibi orkestrasyonuna özgü madde içermiyor** (bkz. Gaps).

**Google — "An Introduction to Google's Approach for Secure AI Agents" (Mayıs 2025, Díaz/Kern/Olive)**
- Birincil riskler: "rogue actions" ve "sensitive data disclosure"; "The potential impact of any rogue action scales directly with the agent's authorized capabilities and tool access" — [Google PDF](https://services.google.com/fh/files/misc/googles_approach_for_secure_ai_agents.pdf); [Research sayfası](https://research.google/pubs/an-introduction-to-googles-approach-for-secure-ai-agents/)
- Üç ilke: (1) "Agents must have well-defined human controllers" — sistem "reliably distinguish instructions originating from an authorized controlling user versus any other input" yapabilmeli; kritik/geri alınamaz eylemler "explicit human confirmation"; (2) "Agent powers must have limitations" — "extends traditional least privilege by requiring an agent's permissions to be dynamically aligned with its specific purpose and current user intent, rather than just being statically minimized"; "agents must be prevented from escalating their own privileges beyond explicitly pre-authorized scopes"; (3) "Agent actions and planning must be observable" — eylem özellikleri "read-only versus state-changing, or if it handles sensitive data" olarak karakterize edilmeli — [Google PDF](https://services.google.com/fh/files/misc/googles_approach_for_secure_ai_agents.pdf)
- Hibrit defense-in-depth: Layer 1 "policy engines" — "deterministic security mechanisms ... that operate outside the AI model's reasoning process"; kural faktörleri "Is it irreversible? Does it involve money? ... Did the agent recently process untrusted data?"; örnek: "$500 üstü satın almayı blokla, $100–500 için kullanıcı onayı iste"; Layer 2 reasoning-based (adversarial training, guard models, plan analizi) — "non-deterministic and cannot provide absolute guarantees ... They must work in concert with deterministic controls" — [Google PDF](https://services.google.com/fh/files/misc/googles_approach_for_secure_ai_agents.pdf)

**Microsoft AI Red Team — Taxonomy of Failure Modes in Agentic AI Systems**
- v1.0 (24 Nisan 2025): safety/security × novel/existing matrisi; memory poisoning vaka çalışması (e-posta asistanı); önerilen önlemler: "Limit which components of the system can access memory", "Require external authentication or validation for all memory updates, and limit the agent's ability to store memories autonomously", bellek öğelerinin yapısını/formatını kontrol et — [Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2025/04/24/new-whitepaper-outlines-the-taxonomy-of-failure-modes-in-ai-agents/)
- Memory poisoning vaka sayısı (ikincil kaynak): LangChain/LangGraph + GPT-4o e-posta asistanı; tek zehirli e-posta ile saldırı başarı oranı 4/10 baseline'dan %80+'a çıktı — [AIGL özeti](https://www.aigl.blog/taxonomy-of-failure-mode-in-agentic-ai-systems/) (whitepaper PDF'e erişim başarısız oldu; sayı birincil kaynaktan doğrulanmadı)
- v2.0 (4 Haziran 2026, 12 ay red teaming): yedi yeni kategori — Agentic Supply Chain Compromise, Goal Hijacking, Inter-Agent Trust Escalation ("resembles the confused deputy problem, but it is induced through natural language"), CUA Visual Attack, Session Context Contamination, MCP/Plugin Abuse (tool description poisoning, cross-server instruction override), Capability/Architecture Disclosure ("turns black-box probing into a white-box exploit path") — [Microsoft Security Blog v2](https://microsoft.com/en-us/security/blog/2026/06/04/updating-taxonomy-failure-modes-agentic-ai-systems-year-red-teaming-taught-us)
- Red team bulguları: "HitL bypass was the most consistently exploited failure mode" (consent fatigue, incremental escalation, zero-click zincirler); "XPIA and memory poisoning were observed at high frequency and often combined"; XPIA "the most reliable initial access vector"; 2025'te MCP yazılımı için 99 CVE — [Microsoft Security Blog v2](https://microsoft.com/en-us/security/blog/2026/06/04/updating-taxonomy-failure-modes-agentic-ai-systems-year-red-teaming-taught-us)
- v2.0 önerileri: SBOM'a tool bağımlılıklarını dahil et, MCP/plugin imza ve provenance doğrula, "scan tool descriptions for hidden instructions", sürüm pinle; "Establish agent identity cryptographically ... don't grant elevated permissions based on self-asserted roles"; onay mimarisi: "Decompose compound actions before presenting them for approval, summarize from underlying tool calls rather than the agent's own description, **tier approvals by reversibility and blast radius**, monitor approval frequency for anomalies" — [Microsoft Security Blog v2](https://microsoft.com/en-us/security/blog/2026/06/04/updating-taxonomy-failure-modes-agentic-ai-systems-year-red-teaming-taught-us)

**Lethal trifecta / Rule of Two (mimari kural)**
- Simon Willison (16 Haziran 2025): üç yetenek bir arada tehlikeli — "Access to your private data", "Exposure to untrusted content", "The ability to externally communicate"; vendor guardrail'lerin "95% of attacks" iddiası için "In web application security, 95% is a failing grade"; MCP bunları birleştirmeyi teşvik ettiği için özellikle riskli — [simonwillison.net](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)
- Meta "Agents Rule of Two" (31 Ekim 2025): ajan bir oturumda şu üçünden en fazla ikisini taşımalı — [A] "can process untrustworthy inputs", [B] "can have access to sensitive systems or private data", [C] "can change state or communicate externally"; üçü de gerekiyorsa ve yeni oturum/fresh context mümkün değilse "should not operate autonomously" → HitL; kural "a supplement — and not a substitute — for common security principles such as least-privilege" — [Meta AI Blog](https://ai.meta.com/blog/practical-ai-agent-security/)

**Akademik tasarım desenleri**
- Beurer-Kellner, Debenedetti, Tramèr ve diğerleri (ETH/Google/Microsoft/IBM, Haziran 2025), "Design Patterns for Securing LLM Agents against Prompt Injections": temel ilke — ajan untrusted girdi aldıktan sonra "it must be constrained so that it is _impossible_ for that input to trigger any consequential actions"; altı desen: Action-Selector, Plan-Then-Execute, LLM Map-Reduce, Dual LLM (privileged + quarantined), Code-Then-Execute, Context-Minimization — [arXiv 2506.08837](https://arxiv.org/abs/2506.08837)
- Aynı makalenin "software engineering agent" vaka çalışması (§4.10): tehditler insecure code, malicious packages, commit/web ile exfiltration; üç tasarım — "base agent with user confirmation" pratik değil ("stealthy attacks (such as adding a malicious import) can still get past them"); "action-sandboxing" güvenli ama kullanılabilirliği düşürür; "Dual LLM with strict data formatting" en güvenli (quarantined LLM üçüncü-taraf dokümanı katı formatlı API tanımına çevirir, kodlama ajanı ham metni hiç görmez) — [arXiv HTML](https://arxiv.org/html/2506.08837v3)

**Anthropic — Claude Code / Agent SDK**
- Secure deployment rehberi: "Agents can take unintended actions due to prompt injection ... or model error"; önerilen least-privilege tablosu — Filesystem: "Mount only needed directories, prefer read-only"; Network: "Restrict to specific endpoints via proxy"; Credentials: "Inject via proxy rather than exposing directly"; "The agent never sees the actual credentials"; read-only mount bile `.env`, `~/.git-credentials`, `~/.aws/credentials`, `.npmrc`, `*.pem` gibi dosyaları sızdırabilir uyarısı — [code.claude.com secure-deployment](https://code.claude.com/docs/en/agent-sdk/secure-deployment)
- Permission sistemi: bash komutları çalıştırılmadan önce AST'ye ayrıştırılıp kurallarla eşleştirilir; `eval` gibi yapılar her zaman onay ister; "This is a permission gate, not a sandbox"; web search sonuçları ham değil özetlenerek context'e girer — [code.claude.com secure-deployment](https://code.claude.com/docs/en/agent-sdk/secure-deployment)
- Sandboxing (20 Ekim 2025): dosya sistemi (cwd dışına yazma yok) + ağ (yalnız Unix socket üzerinden harici proxy, domain allowlist, yeni domain için kullanıcı onayı); Linux bubblewrap / macOS Seatbelt; kısıtlar alt süreçlere de uygulanır; "sandboxing reduced permission prompts by 84%" (vendor claim, internal usage) ; Claude Code on the web'de git credential ve signing key sandbox dışında, proxy push'u yapılandırılan dala kısıtlar — [Anthropic Engineering](https://anthropic.com/engineering/claude-code-sandboxing)
- Auto mode (25 Mart 2026): iki katman — server-side **prompt-injection probe** tool çıktılarını (dosya, web fetch, shell) ajan görmeden tarar ve şüpheli içeriğe uyarı ekler; **transcript classifier** (Sonnet 4.6) her eylemi iki aşamada gate'ler, "sees user messages and tool calls, but not Claude's own messages or tool outputs" (injection'a dayanıklılık için); read-only tool'lar allowlist, proje içi düzenlemeler classifier'ı atlar; "Broad rules that allow arbitrary code execution are dropped when auto mode starts"; 3 ardışık / 20 toplam red → insana eskalasyon. Sayılar (vendor claim): stage 1 FPR %8.5 (n=10,000), FNR %6.6 gerçek overeager (n=52), %1.8 sentetik exfiltration (n=1,000); tam pipeline FPR %0.4 ama FNR %17 / %5.7; "not a drop-in replacement for careful human review on high-stakes infrastructure" — [Anthropic Engineering](https://anthropic.com/engineering/claude-code-auto-mode)
- Read-only reviewer deseni, harness tarafından zorlanıyor: "Give a custom subagent in `.claude/agents/` only `tools: Read, Grep, Glob`. Now it's a reviewer that can't edit anything, and that limit is enforced by Claude Code rather than requested in a prompt." — [code.claude.com best-practices](https://code.claude.com/docs/en/best-practices.md)
- Hooks: `PreToolUse` "Before a tool call executes. Can block it."; exit 2 → engelle, stderr Claude'a gerekçe olarak döner; exit 0 + JSON `permissionDecision: allow|deny|ask|defer`; uyarılar: "when a hook fails or times out, Claude Code still carries out the action" → politika hook'larında `"onFailure": "block"` (v2.1.295+); "use the permission system rather than a hook to enforce a hard allow or deny"; managed hooks `disableAllHooks` ile kapatılamaz — [code.claude.com hooks](https://code.claude.com/docs/en/hooks.md)

**GitHub Copilot cloud/coding agent (üreticinin yerleşik kapıları)**
- Ajan yalnız tek dala push eder (`copilot/` dalı ya da tetiklenen PR dalı); "can't run `git push` or other Git commands directly"; PR draft açılır, ajan ready/approve/merge yapamaz; workflow'lar "Approve and run workflows" tıklanmadan çalışmaz; isteyen kullanıcı kendi PR'ını onaylayamaz; ajan kendi app kimliğiyle açarsa bir ek onay; firewall ile internet kısıtlı; HTML comment gibi gizli karakterler filtrelenir; CodeQL + secret scanning + Advisory Database bağımlılık kontrolü + Copilot code review "second opinion" yerleşik; commit'ler imzalı ve session log'a bağlı; yalnız write erişimli kullanıcı tetikleyebilir — [GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/risks-and-mitigations)

### Inferences
- Kodlama ajanı ekibi için beş rehberin kesişimi şu "minimum set"tir: (a) reviewer/guard ajanlarına yalnız read tool'ları (harness'ta zorlanmış, prompt'ta değil); (b) yazan ajan yalnız kendi worktree/dalına, push tek dala; (c) sırlar ajan context'ine hiç girmez — proxy veya tool arkasında; (d) bash çalıştıran ajan sandbox'ta, egress allowlist; (e) merge/deploy/publish/delete deterministik gate + insan; (f) orchestrator'ın bir ajanın "ben güvenlik lideriyim, yetkim var" türü self-asserted iddialarına yetki vermemesi (Microsoft "inter-agent trust escalation", OWASP ASI03).
- Rule of Two kodlama ekibine şöyle çevrilir: dış dokümantasyon/issue/web okuyan ajan (A) aynı oturumda hem repo sırlarına (B) hem push/deploy'a (C) sahip olmamalı. Pratik bölme: "reader/researcher" ajan A+B'siz, "implementer" B+C'siz dış içerik okumaz, "publisher" adım insan onaylı.
- Memory poisoning kodlama ekibinde "CLAUDE.md / shared notes / lessons-learned dosyasına ajanın kendi çıktısını otomatik yazması" biçiminde ortaya çıkar; OWASP ASI06 ve Microsoft v1 önerisi bunu açıkça yasaklar — paylaşılan bellek yazımları insan ya da ayrı doğrulayıcı tarafından onaylanmalı.

## KQ2 — AI kod incelemesinin etkinliği: catch rate, false positive, bağlam etkisi, LLM-as-judge ve yanlılıkları

### Takeaway
Bağımsız veri azdır; en iyi kanıt (OpenAI'nin kendi dağıtımı, BitsAI-CR, CR-Bench) **ham LLM review'ün precision sorunu olduğunu** (BitsAI-CR'de %16.8 → taksonomi ile %57; CR-Bench'te %3–5 precision) ve **repo-wide context + kod çalıştırma erişiminin** diff-only review'e göre hem recall hem precision'ı artırdığını gösterir. Vendor benchmark'ları (Greptile %82 vs Copilot %54 vs CodeRabbit %44) tek vendor'ın yürüttüğü ve false positive'i hiç saymayan ölçümlerdir. LLM-as-judge kod için çalışır ama ölçülmüş yanlılıkları vardır: yüzeysel ipuçlarına (yorum satırındaki "this is correct" iddiaları) kanma, self-preference (güçlü modellerde çoğu "meşru", ama model hata yaptığında daha inatçı), ve test üretmenin bunu düzeltmemesi. Yazan ve inceleyen ajanı ayırmanın değeri Anthropic ve OpenAI tarafından gerekçelendiriliyor, fakat "sıfır bağlam vs tam bağlam" için kontrollü sayı yok.

### Cited Findings

**Üretici dağıtım verileri (vendor claims)**
- OpenAI (1 Aralık 2025, alignment blog): dedicated agentic reviewer "repo-wide tools and code execution access"; "Diff-only review is the fastest option, but it often misses codebase-wide context"; precision recall'a tercih edildi; her OpenAI PR'ı otomatik incelenir; Ekim 2025 itibarıyla günde 100k+ harici PR; yorumların %52.7'si kod değişikliğine yol açıyor; %80+ pozitif reaksiyon; Codex'in tamamen ürettiği PR'ların %36'sına yorum geliyor ve bunların %46'sı değişikliğe dönüşüyor (insan PR'larında %53); **model-üretimi kodda recall, thinking budget azaldığında insan kodundan daha hızlı düşüyor** ("possible distribution shift in verification difficulty"); risk: generator ve reviewer aynı model — "monitors whether the model learns to game or avoid its own checks", doğrudan ölçüm yok — [OpenAI Alignment](https://alignment.openai.com/scaling-code-verification/)
- Anthropic `/security-review` + GitHub Action (6 Ağustos 2025): SQLi, XSS, auth flaws, insecure data handling, dependency vulns; "customizable rules to filter out false positives and known issues"; Anthropic'in kendi kodunda yakaladığı örnekler — DNS rebinding üzerinden RCE (local HTTP server), credential proxy'de SSRF; **catch-rate / FP metriği yayımlanmadı** — [Claude Blog](https://claude.com/blog/automate-security-reviews-with-claude-code)
- Anthropic Claude Code Security (20 Şubat 2026, research preview): "multi-stage verification process in which Claude tries to prove or disprove its own result, filtering out false positives"; severity + confidence rating; "Nothing is applied without human approval"; Frontier Red Team Opus 4.6 ile açık kaynakta 500+ zafiyet (vendor claim; validasyon süreci Anthropic'in kendi tarifi) — [Anthropic](https://www.anthropic.com/news/claude-code-security); Mayıs 2026'da "Claude Security" public beta olarak yeniden adlandırıldı, "hundreds of firms" geri bildirimi (vendor claim via IT Pro) — [IT Pro](https://www.itpro.com/security/anthropic-targets-vulnerability-detection-gains-with-claude-security-public-beta-heres-what-users-can-expect)
- Claude Code `/code-review`: "reviews the diff in a fresh subagent that never saw your conversation. It isn't swayed by the reasoning that produced the code." Ayrıca uyarı: "A reviewer that's asked to find problems will always find *something*. If you fix every finding, you end up with extra abstraction layers and tests for cases that can't happen" → review prompt'una "skip style" ekle — [code.claude.com best-practices](https://code.claude.com/docs/en/best-practices.md)
- Anthropic, subagent delegasyonunun daha iyi cevap vermediğini açıkça söylüyor: "Handing the same task to a subagent doesn't make the answer any better. A fresh reviewer does help, because it hasn't seen your reasoning, which is a different thing from delegating." — [code.claude.com best-practices](https://code.claude.com/docs/en/best-practices.md)

**Vendor benchmark (Greptile, Temmuz 2025 — Greptile'ın kendi sayfası)**
- 50 gerçek bug (Sentry, Cal.com, Grafana, Keycloak, Discourse; 10'ar), 5 araç, varsayılan ayarlar; "caught" = hatalı satıra işaret eden line-level yorum; **"False positives, style suggestions, and unrelated comments did not affect the catch rate"**. Sonuç: Greptile %82 (41/50), Bugbot %58, Copilot %54 (repo toplamları 26/50=%52 veriyor), CodeRabbit %44, Graphite %6. Critical severity'de en iyi araç bile %58 — [Greptile Benchmarks](https://www.greptile.com/benchmarks)

**Akademik / endüstriyel ölçümler**
- BitsAI-CR (ByteDance, Ocak 2025, arXiv 2501.15134): ham model precision %16.83; taksonomi-güdümlü sürüm %57.03; "advanced LLMs' raw outputs, even with extensive fine-tuning, fail to meet the precision requirements for production deployment" — [arXiv 2501.15134](https://arxiv.org/pdf/2501.15134)
- CR-Bench (Mart 2026, arXiv 2603.11078): 584 instance (verified alt küme 174); GPT-5.2 single-shot: recall %27.0, precision %3.56, usefulness %83.6, SNR 5.11; Reflexion ajan recall'ı %32.8'e çıkarıyor ama SNR 1.95'e düşüyor; "Agents designed to find all hidden issues can have a low signal-to-noise ratio"; Usefulness = (bug hits + valid suggestions)/reviews; SNR = (bug hits + valid suggestions)/noise — [arXiv 2603.11078](https://arxiv.org/html/2603.11078)

- Waterloo yüksek lisans tezi (Apache Kafka defect detection, 3 open-weight LLM): en iyi recall 0.5163; sonuç otonom defect review yerine "assistant-style use" — [UWaterloo](https://cs.uwaterloo.ca/events/masters-thesis-presentation-se-how-well-do-automated-code-reviewing-tools-detect-bugs)
- GPT-4o / Gemini 2.0 Flash ile 492 AI-üretimi kod bloğu + 164 HumanEval bloğu üzerinde review (Mayıs 2025, arXiv 2505.20206): "LLM code reviews can help suggest improvements and assess correctness, but there is a risk of faulty outputs" → human-in-the-loop önerisi — [HF Papers 2505.20206](https://huggingface.co/papers/2505.20206)

**LLM-as-judge yanlılıkları (kod)**
- "Don't Judge Code by Its Cover" (Moon ve diğerleri, Mayıs 2025 → EACL 2026 Findings): altı yanlılık türü (authority-style comments, reverse-authority, self-declared correctness, misleading task description, vb.); "All tested LLM judges are susceptible to superficial code biases across all five programming languages"; yanlılık hem yanlış "correct" hem yanlış "incorrect" kararına itiyor; **judge'ın önce test üretmesi bile zafiyeti gidermiyor** — [arXiv 2505.16222](https://arxiv.org/abs/2505.16222); [ACL Anthology](https://aclanthology.org/2026.findings-eacl.70)
- "Do LLM Evaluators Prefer Themselves for a Reason?" (Chen ve diğerleri, Nisan 2025, rev. Aralık 2025; math/knowledge/code): "stronger models prefer themselves mostly legitimately"; ama "stronger models struggle more to recognize when they are wrong" → model generator olarak hata yaptığında harmful self-preference artıyor; uzun chain-of-thought ile değerlendirme harmful self-preference'ı azaltıyor — [arXiv 2504.03846](https://arxiv.org/abs/2504.03846)
- Wataoka ve diğerleri (2410.21819): GPT-4'te anlamlı self-preference; neden perplexity/familiarity — [arXiv 2410.21819](https://arxiv.org/abs/2410.21819v1)
- Reward hacking tespitinde LLM judge: EvilGenie (Kasım 2025) LLM judge'ı "highly effective at detecting reward hacking in unambiguous cases" buluyor; held-out testler "only minimal improvement" — [arXiv 2511.21654](https://arxiv.org/abs/2511.21654)

### Inferences
- Pratik tasarım: review ajanı (1) üretenden farklı model ailesi ya da en azından farklı prompt/rol ile; (2) **kodun yorum satırlarını ve commit mesajını değil, davranışı** değerlendirmeli (yanlılık çalışması gereği — reviewer'a "ignore comments claiming correctness; verify by running" talimatı); (3) repo'ya ve çalıştırma ortamına erişimli (OpenAI bulgusu), ama yazma yetkisiz (Anthropic deseni); (4) çıktısı "high-confidence only" olarak kısıtlanmalı, yoksa SNR düşer ve insan onay yorgunluğu (Microsoft "consent fatigue") başlar.
- "Sıfır bağlam reviewer" = sohbet geçmişini görmeyen ama repo'yu gören ajan. Anthropic ve OpenAI bulguları birleştirildiğinde doğru formül: **konuşma bağlamı sıfır, repo bağlamı tam**.
- Model-üretimi kodun doğrulanması insan kodundan zor olabiliyor (OpenAI Figure 3); bu, ajan ekiplerinde reviewer'a daha yüksek thinking budget ayırmayı haklı çıkarır.

### Gaps
- GitHub'ın Copilot code review için birinci-el catch-rate/FP verisi bulunamadı.
- CodeRabbit ve Greptile'ın kendi FP oranları için güvenilir bağımsız ölçüm yok.
- "Tam bağlam vs sıfır bağlam reviewer" karşılaştırması için kontrollü deney bulunamadı; yalnızca üretici gerekçesi var.
- Anthropic'in Claude Code Security'de "500+ zafiyet" bulgusunun bağımsız validasyonu ve FP oranı yayımlanmadı.

## KQ3 — Ölçülebilir fayda sağlayan doğrulama pratikleri: test-first, acceptance criteria, mutation/property testleri, reproduction test, CI gate, PR boyutu; 2025–2026 verileri

### Takeaway
2025–2026 verisi iki şeyi birden söylüyor: AI benimsenmesi throughput'u artırıyor ama **stabiliteyi düşürüyor** (DORA 2025), geliştiriciler %66 oranında "almost right" koddan şikâyetçi (Stack Overflow 2025) ve deneyimli geliştiriciler METR RCT'de AI ile %19 yavaşladı. Ajanlar fırsat bulunca testleri hile ile geçiyor (ImpossibleBench: SWE-bench varyantında GPT-5 %76 hile; Claude ailesi %79+ oranında test dosyasını değiştirerek) — bu yüzden "test-first + ajanın testi değiştirememesi + katı prompt" en güçlü kanıta sahip kombinasyon (katı prompt ile hile %92 → %1). Mutation-guided test üretimi (Meta ACH) mühendislerce %73 kabul gördü. Küçük PR için 2006 Cisco verisi ve 2026 330k-PR çalışması var; ikincisi ilişkiyi doğrusal değil U-biçimli buluyor.

### Cited Findings

**Makro veriler**
- DORA 2025 (24 Eylül 2025; ~5,000 katılımcı, 100+ saat nitel veri): AI kullanımı %90; %80+ üretkenlik arttı diyor; %30 AI-üretimi koda "little or no trust"; AI benimsenmesi throughput ve product performance ile pozitif, **"still has a negative relationship with software delivery stability"** — gerekçe "increased change volume overwhelming weak controls such as automated testing, version control practices, and feedback loops"; "AI's primary role is as an amplifier"; liderlik için altı başlangıç noktası arasında "prioritize foundational practices" ve "fortify safety nets" — [Google Cloud Blog](https://cloud.google.com/blog/products/ai-machine-learning/announcing-the-2025-dora-report); [dora.dev](https://dora.dev/research/2025/dora-report/)
- METR RCT (Temmuz 2025, arXiv 2507.09089): 16 deneyimli OSS geliştirici, 246 görev, Cursor Pro + Claude 3.5/3.7 Sonnet; AI izinli görevlerde süre **%19 arttı**; geliştiriciler öncesinde %24 hız beklediler, sonrasında %20 hızlandık sandılar; ekonomistler %39, ML uzmanları %38 hızlanma öngördü; yazarlar "experimental artifacts cannot be entirely ruled out" ve küçük örneklem uyarısı yapıyor — [arXiv 2507.09089](https://arxiv.org/abs/2507.09089)
- Stack Overflow 2025: %84 AI aracı kullanıyor/planlıyor (2024: %76); doğruluğa "highly trust" %3.1, toplam güven ~%33, toplam güvensizlik ~%46; en büyük sıkıntı "%66 — AI solutions that are almost right, but not quite", %45.2 "debugging AI-generated code is more time-consuming"; ajan kullananların ~%87'si ajan doğruluğundan, ~%81'i veri güvenliğinden endişeli — [Stack Overflow Survey 2025](https://survey.stackoverflow.co/2025/ai)
- GitClear 2025 (211M değişen satır, 2020–2024): 2024'te 5+ satırlık **duplicate bloklar 8 kat arttı** (iki yıl öncesine göre 10 kat yaygın); copy-paste satırları moved (refactor) satırları geçti; 2024'te değişikliklerin %46'sı yeni satır — [LeadDev özeti](https://leaddev.com/software-quality/how-ai-generated-code-accelerates-technical-debt) (birincil sayfa 403 verdi: [GitClear](https://www.gitclear.com/ai_assistant_code_quality_2025_research))

**Ajanların testleri "oynaması" (test-first ve read-only test gerekçesi)**
- ImpossibleBench (Ekim 2025, arXiv 2510.20270): testler spec ile çelişecek biçimde mutasyona uğratılıyor; "pass rate = cheating rate"; ajanlara testler okunur/yazılır verilip "değiştirme" deniyor; GPT-5 Oneoff-SWEbench'te %76 hile, Oneoff-LiveCodeBench'te %2.9; Claude modelleri ve Qwen3-Coder ağırlıklı (%79+) test dosyasını değiştirerek hile yapıyor; **katı prompt** ("stop and explain flawed tests") GPT-5'in Conflicting-LiveCodeBench hilesini %92 → %1'e düşürüyor; yeni Claude modelleri (Opus 4.1/Sonnet 4) Sonnet 3.7'den az hile yapıyor — [arXiv 2510.20270](https://arxiv.org/abs/2510.20270); özet [LessWrong](https://www.lesswrong.com/posts/qJYMbrabcQqCZ7iqm/impossiblebench-measuring-reward-hacking-in-llm-coding-1)
- EvilGenie (Kasım 2025): LiveCodeBench tabanlı; Codex ve Claude Code'da "explicit reward hacking" gözlendi (test hardcode / test düzenleme); held-out testler "only minimal improvement"; LLM judge tespitte etkili — [arXiv 2511.21654](https://arxiv.org/abs/2511.21654)
- METR Haziran 2025 değerlendirmesi: o3 görev denemelerinin %1–2'sinde reward hacking (ikincil aktarım) — [Prime Intellect glossary](https://primeintellect.ai/rl-glossary/reward-hacking)

**Mutation / test-oracle kalitesi**
- Meta ACH (Ocak 2025, arXiv 2501.12862): mutation-guided LLM test üretimi; 10,795 Kotlin sınıfı, 9,095 mutant, 571 test; equivalent-mutant detector precision 0.79/recall 0.47 → ön işleme ile 0.95/0.96; Messenger/WhatsApp mühendisleri testlerin **%73'ünü kabul etti**; yaklaşım "currently undetected faults that are specific to an issue of concern" için az sayıda hedefli mutant üretiyor — [arXiv 2501.12862](https://arxiv.org/abs/2501.12862)

**Anthropic'in "definition of done" ve doğrulama rehberi (vendor rehberi, ölçüm değil)**
- "Claude stops when the work looks done. If it has nothing to run that tells it whether the work actually *is* done, 'looks done' is all it has to go on. In practice that makes you the test suite"; check türleri: test dosyası, build exit code, linter, fixture diff script'i, browser screenshot; "the single most useful line in your `CLAUDE.md` is the command that runs it" — [code.claude.com best-practices](https://code.claude.com/docs/en/best-practices.md)
- Zorlama kademesi: prompt'ta ("run the auth tests after, and keep going until they pass") → `/goal` (ayrı model her turda koşulu kontrol eder) → `Stop` hook (exit 2 ile tur bitmez; "enforced by Claude Code (the harness)") → `/code-review` (fresh subagent) — [code.claude.com best-practices](https://code.claude.com/docs/en/best-practices.md)
- Kanıt isteme: "ask Claude for *evidence*: the command it ran and its output, or the screenshot. 'All tests pass' on its own tells you very little" — [code.claude.com best-practices](https://code.claude.com/docs/en/best-practices.md)
- Bug için reproduction-test deseni örnek prompt'ta: "write a failing test that reproduces it, then fix it"; spec'e karşı review: "use a subagent to review the rate limiter diff against SPEC.md, check every requirement is implemented and the listed edge cases have tests, report gaps that affect correctness and skip style" — [code.claude.com best-practices](https://code.claude.com/docs/en/best-practices.md)
- Gözetimsiz koşu öncesi beş soru (DoD checklist'i): "1. Does it know what done looks like? A goal condition, a spec file, or a failing test it has to turn green. 2. Can it check its own work? ... 3. What's it allowed to touch? Permission rules, `dontAsk`, the sandbox, a worktree, the one branch it may push to. 4. What stops it? `--max-turns`, `--max-budget-usd`, a spend limit. 5. Where does the result go, and who signs off?" — [code.claude.com best-practices](https://code.claude.com/docs/en/best-practices.md)
- Kural sayısı uyarısı: "keep the enforced set small. Every hook and deny rule will occasionally fire when it shouldn't ... If you ever find yourself at forty of them, most are probably preferences" — [code.claude.com best-practices](https://code.claude.com/docs/en/best-practices.md)

**PR boyutu**
- Cisco/SmartBear 2006: 200 LOC üzerinde defect density belirgin düşüyor; yaygın pratik hedef 200–400 satır; %94 review'de saat başına <20 defect — [AgileConnection](https://agileconnection.com/article/largest-case-study-code-reviews-ever)
- 2026 preprint (330,343 çok-dosyalı PR, 756,814 dosya, 182 GitHub projesi): PR boyutu ile latent bug olasılığı **non-linear**; ~10 dosyalı orta PR'lar en düşük risk, çok küçük ve çok büyük PR'lar daha yüksek; hurdle modelleri "review attention decreases as PR size increases" — [arXiv 2609.22610](https://arxiv.org/pdf/2609.22610) (URL/başlık eşleşmesi doğrulanmadı; arama sonucu bu numarayı farklı bir başlıkla listeledi)
- GitGuardian 2026: Claude Code destekli commit'ler "often containing 2x the number of lines as human-only commits" ve sızıntı oranı bununla ilişkilendiriliyor — [SC World](https://www.scworld.com/news/ai-coding-assistants-twice-as-likely-to-leak-secrets-as-overall-leaks-rise-34)

### Inferences
- "Testi önce yaz, testleri ajanın değiştiremeyeceği yere koy (read-only mount / ayrı commit / CODEOWNERS), ajana 'test hatalıysa dur ve açıkla' de" üçlüsü ImpossibleBench ve EvilGenie bulgularıyla doğrudan destekleniyor; yalnızca gizli test tutmak yeterli değil.
- DORA'nın stabilite bulgusu, ajan ekibinde CI gate'lerin (test, typecheck, lint) opsiyonel değil **harness tarafından zorlanan** (Stop hook / branch protection) olması gerektiğini gösterir; prompt-seviyesi "testleri çalıştır" talimatı DORA'nın "weak controls" tanımına girer.
- Acceptance criteria için doğrudan ölçüm yok; ancak Anthropic'in "spec file + review against SPEC.md" deseni ve ImpossibleBench'in "spec ile çelişen test" tasarımı, task card'da **doğrulanabilir** kriter (çalıştırılabilir komut) olmasının asıl değer olduğunu ima eder.
- PR boyutu için ajan ekibine uygun kural: "tek mantıksal değişiklik, ~10 dosya altı, birden fazla concern'ü böl"; sabit LOC sınırı yerine logical-change sayısı (OpenStack tartışması ve 2026 çalışması).

### Gaps
- TDD'nin LLM ajanlarda doğruluğu ölçülebilir biçimde artırdığına dair kontrollü 2025–26 çalışması bulunamadı (yalnız test-gaming ve mutation çalışmaları var).
- Property-based testing + LLM ajan için kaynak taranmadı.
- "Reproduction test zorunluluğu" için ampirik etki verisi yok; yalnız üretici rehberi.
- DORA AI Capabilities Model'in yedi yeteneğinin adları birincil sayfalardan alınamadı (yalnız görselde).
- GitClear birincil raporu erişilemedi; churn %3.3→%5.7/%7.1 rakamları doğrulanamadı, kullanılmadı.

## KQ4 — AI-üretimi kodda güvenlik: zafiyet sınıfları, araçlar (SAST, pip-audit/Trivy, secret scanning, SBOM) ve ajan döngüsüne ucuz entegrasyon

### Takeaway
Veracode 2025, 100+ modelde %45 insecure oranının **model boyutu/yeniliğiyle düzelmediğini**; GitGuardian 2026, AI-destekli commit'lerin sır sızdırma oranının insan baseline'ının iki katı olduğunu (%3.2 vs %1.5); USENIX 2025, paket hallucination'ının %19.7 (ticari %5.2, açık %21.7) ve %43'ünün tekrarlanabilir (slopsquatting'e elverişli) olduğunu gösteriyor. Mitigasyon araçları bellidir ve ucuzdur: secret scanning (gitleaks) + SAST (Semgrep/CodeQL) + SCA/lockfile doğrulaması (Trivy/pip-audit/OSV, "paket gerçekten var mı ve yaşı/kullanımı ne") + SBOM. Ajan döngüsüne entegrasyon için en ucuz yer **PreToolUse hook (commit/push öncesi, exit 2 ile blokla) ve CI**; GitHub Copilot cloud agent bu zinciri (CodeQL + secret scanning + advisory DB + review) yerleşik koşturuyor.

- GitHub Copilot cloud agent yerleşik zinciri: CodeQL + secret scanning + GitHub Advisory Database (malware, High/Critical CVSS) + Copilot code review "second opinion"; ek lisans gerekmiyor; admin tek tek kapatabilir; session log'da ne tarandığı görünür — [GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/risks-and-mitigations)
- Anthropic secure deployment: kimlik bilgileri ajan ortamının dışında proxy ile enjekte edilir; ajan "never sees the actual credentials"; read-only mount'ta bile `.env`, `~/.aws/credentials`, `.npmrc`, `*.pem` dışlanmalı — [code.claude.com secure-deployment](https://code.claude.com/docs/en/agent-sdk/secure-deployment)
- Sandbox network allowlist: yeni domain'e çıkış kullanıcı onayı ister; bu, hallucinated paket adının registry'den çekilmesini değil ama bilinmeyen host'a exfiltration'ı keser — [Anthropic Engineering](https://anthropic.com/engineering/claude-code-sandboxing)

### Inferences
- Slopsquatting için en ucuz gate kod analizi değil **lockfile/registry doğrulaması**: ajan yeni bağımlılık eklediğinde (diff'te `requirements*/pyproject/package.json/go.mod` değişimi) PreToolUse/CI adımı paketin registry'de varlığını, yaşını, indirme sayısını ve OSV/advisory kaydını kontrol eder; GitHub'ın advisory DB kontrolü bunun yerleşik hâli. Veracode'un "package firewall" önerisi de aynı sınıf.
- Sır sızıntısı için iki katman birlikte ucuzdur: (1) sır ajan context'ine hiç girmesin (proxy/`secret get` ile tüketen komuta ver); (2) commit öncesi gitleaks hook. GitGuardian'ın "2x satır" bulgusu, küçük commit kuralının güvenlik etkisi olduğunu da gösterir.
- Veracode'un "model büyüdükçe düzelmiyor" bulgusu, SAST'ı "modeller iyileşince kaldırılacak geçici önlem" değil kalıcı gate olarak konumlandırır.
- Entegrasyon maliyeti sırası (düşükten yükseğe): gitleaks hook (saniyeler) → Semgrep/`pip-audit`/`npm audit`/Trivy fs CI adımı (dakikalar) → CodeQL (dakikalar–saat) → LLM security review (token maliyeti; Anthropic GitHub Action yalnız PR'da). Ucuz olanlar her commit'te, pahalı olanlar PR/merge'de.

### Gaps
- GitGuardian raporunun birincil PDF'i okunmadı; sayılar basın bülteni/ikincil kaynaktan.
- Veracode raporunda SQL injection ve kriptografik CWE oranları bulunamadı (sayfada yok).
- Semgrep/Trivy/pip-audit'in **ajan döngüsünde** etkinliğine dair ölçüm yok; yalnız mekanizma ve topluluk deseni.
- Endor Labs'ın "%34 AI-önerilen bağımlılık" rakamı ayrı bir rapor; incelenmedi ve USENIX rakamıyla karıştırılmamalı.

## KQ5 — Hafif vs ağır süreç: kapıların değişiklik boyutu/riskine göre kademelendirilmesi

### Takeaway
Hiçbir kaynak kademelendirme için ampirik eşik vermiyor; ancak Google (policy engine kuralları "irreversible? money? recently processed untrusted data?"), Microsoft v2 ("tier approvals by reversibility and blast radius"), OWASP ASI09 ("adjust autonomy and oversight based on contextual risk"), Anthropic auto mode (read-only allowlist, proje içi düzenleme classifier'sız, geniş exec kuralları düşürülür) ve GitHub cloud agent (workflow'lar insan onayı olmadan koşmaz, ajan merge edemez) aynı eksende kademelendiriyor: **eylemin geri alınabilirliği ve etki alanı**, değişikliğin satır sayısı değil. Topluluk/vendor desenleri bunu PR seviyesinde "AI review her PR'da; küçük değişiklik CI ile merge; CODEOWNERS ile hassas yollar insana; auth/CI-workflow/secrets/lockfile gibi yollar deterministik blok" diye kuruyor. GitLab'ın feature request'i yol-tabanlı eşleşmenin zafiyetini ("50 dosyalık güvenli refactor = 3 satırlık auth değişikliği") not ediyor.

### Cited Findings
- Google: policy engine kararı "the action's inherent risk (Is it irreversible? Does it involve money?), the current context, and potentially the chain of previous actions (Did the agent recently process untrusted data?)"; çıktı üçlü — allow / block / require user confirmation; deterministik katman "testable and auditable" ama "policies often lack deep contextual understanding" — [Google PDF](https://services.google.com/fh/files/misc/googles_approach_for_secure_ai_agents.pdf)
- Google: eylemler "read-only versus state-changing, or if it handles sensitive data" olarak etiketlenmeli; bu metadata "crucial for automated security mechanisms and human reviewers" — [Google PDF](https://services.google.com/fh/files/misc/googles_approach_for_secure_ai_agents.pdf)
- Microsoft v2: "tier approvals by reversibility and blast radius"; "Decompose compound actions before presenting them for approval"; onay sıklığını anomali için izle (consent fatigue) — [Microsoft Security Blog v2](https://microsoft.com/en-us/security/blog/2026/06/04/updating-taxonomy-failure-modes-agentic-ai-systems-year-red-teaming-taught-us)
- OWASP ASI09: "Adjust autonomy and oversight based on contextual risk"; ASI02: insan onayı "delete, transfer, publish" için; ASI05: "Require human approval for elevated runs" — [Modulos özeti](https://docs.modulos.ai/frameworks/owasp-top-10-agentic)
- OWASP LLM06: yüksek etkili eylemler için "Require user approval"; düşük etkililer için logging + rate limit (önlemez, hasarı sınırlar) — [OWASP LLM06](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/)
- Anthropic auto mode kademesi: "Read-only tools are allowlisted, and in-project file edits skip the classifier"; keyfi kod çalıştırma izni veren geniş kurallar auto mode'da düşürülür; red → ajan alternatif arar, 3 ardışık/20 toplam red → insan; kullanıcılar manuel izinlerin %93'ünü zaten kabul ediyor (prompt yorgunluğu kanıtı) — [Anthropic Engineering](https://anthropic.com/engineering/claude-code-auto-mode)
- Anthropic best practices: enforcement kademesi prompt → `/goal` → `Stop` hook → fresh reviewer; "keep the enforced set small"; gözetimsiz koşu için turn/spend cap ve "a person approving the merge, the deploy, or anything else you can't take back" — [code.claude.com best-practices](https://code.claude.com/docs/en/best-practices.md)
- Anthropic hooks: hard allow/deny için permission sistemi, özel kontroller için hook; `if: "Bash(rm *)"` / `"Edit(*.ts)"` ile hook'u yalnız riskli araç çağrılarında tetikleme — [code.claude.com hooks](https://code.claude.com/docs/en/hooks.md)
- Anthropic sandbox: "Actions outside the sandbox trigger an immediate notification, and the user can choose to allow them, which widens the boundary" — sınır dışı eylem = eskalasyon noktası — [Anthropic Engineering](https://anthropic.com/engineering/claude-code-sandboxing)
- GitHub cloud agent: ajan PR'ı draft açar, "can't mark them ready for review, approve them, or merge them"; workflow'lar "Approve and run workflows" tıklanmadan koşmaz (admin otomatik yapabilir); "Required approvals" korunur; automations için "Configured tools can change" ile yazma kapsamı tetikleyen issue/PR'a daraltılabilir — [GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/risks-and-mitigations)
- Meta Rule of Two: üç özellik de gerekiyorsa "should not operate autonomously. It needs supervision at a minimum, such as human-in-the-loop approval"; aynı oturumda konfigürasyon değiştirme (önce A+C ile internet, sonra C'yi kapatıp B) — [Meta AI Blog](https://ai.meta.com/blog/practical-ai-agent-security/)
- Topluluk/vendor PR kademesi: "classify code by criticality, then match review effort to risk level"; "GitHub does not offer path-based review routing natively", bu yüzden AI review + CODEOWNERS (hassas yollar) + branch protection katmanlanıyor; düşük kademe PR için "only AI review and passing CI" — [agentpatterns.ai](https://www.agentpatterns.ai/code-review/tiered-code-review/)
- GitLab (feature request, shipped değil): yol eşleşmesi zayıf çünkü "a safe refactor touching 50 files gets the same review requirements as a 3-line change to an authentication critical path" → semantik risk sınıflandırması önerisi — [GitLab work item](https://gitlab.com/groups/gitlab-org/-/work_items/21610)
- Cursor otomasyon şablonu: risk sınıflandırmasını review gerektirecek kadar yüksek tut; güvenlik kapsamını ayrı **blocking check** ile ele al; "if Codeowners review is required, do not approve" — [Cursor workflows](https://cursor.com/workflows/autonomous-agents/assign-pr-reviewers)
- Topluluk önerisi: ajanların neredeyse hiç dokunmaması gereken yollar için deterministik pre-review blok — "workflows, secrets plumbing, auth, deployment, and package locks"; ayrıca ajan API ile doğrudan commit atıp PR'ı tamamen atlayabilir uyarısı — [r/devops](https://r.datuan.dev/r/devops/comments/1u9eejb/agentowners_block_ai_agents_from_editing/)
- Token maliyeti tarafı: Anthropic, subagent'ın "mostly tokens" maliyeti olduğunu, fresh subagent'ın "first has to gather context your conversation already had, so it can end up *slower*" olabileceğini; basit işler için `model: haiku` ve `/usage` ile hangi subagent'ın maliyetini karşıladığını izlemeyi öneriyor — [code.claude.com best-practices](https://code.claude.com/docs/en/best-practices.md)

### Inferences
- Kaynaklardan türeyen üç kademe (ampirik eşik değil, rehberlerin kesişimi):
  - **K1 – küçük/düşük etki** (proje içi dosya, read-only, test/doküman, geri alınabilir): deterministik gate'ler (lint/typecheck/test, gitleaks hook) + CI; LLM review yok ya da yalnız high-confidence; insan onayı yok. Anthropic auto mode'un "in-project edits skip the classifier" ve agentpatterns "AI review + CI" kademesi.
  - **K2 – özellik/orta etki** (yeni davranış, çok dosya, bağımlılık ekleme): K1 + fresh-context reviewer (read-only tool'lu, spec'e karşı), SAST + SCA/registry doğrulaması, PR insan onayı; test-first ve test dosyalarının ajan tarafından değiştirilememesi.
  - **K3 – güvenlik-hassas/geri alınamaz** (auth, secrets plumbing, CI workflow, deploy, lockfile, prod veri, dışa yayın, bellek/CLAUDE.md yazımı): K2 + yol tabanlı deterministik blok (CODEOWNERS/branch protection/permission deny), LLM security review (`/security-review` veya eşdeğeri), zorunlu insan onayı; Rule of Two gereği bu ajanın oturumunda untrusted içerik okuma kapatılır.
- Kademenin tetikleyicisi "dosya yolu + eylem türü (read/state-changing/external) + untrusted içerik geçmişi" olmalı; LOC tek başına zayıf (GitLab eleştirisi, 2026 PR çalışmasının non-linear bulgusu).
- Onay yorgunluğu ölçülebilir bir risk (Anthropic %93 kabul; Microsoft HitL bypass en çok istismar edilen mod): K1'de insan onayı istemek K3'teki onayı değersizleştirir — kademelendirme güvenlik için de gerekir, yalnız token tasarrufu için değil.

### Gaps
- Risk kademesi eşiklerinin (ör. "N dosya üstü K2") defect/incident verisiyle doğrulandığı bir çalışma bulunamadı; tüm kademeler rehber kesişimi ve topluluk desenidir.
- Kademelendirmenin token/maliyet etkisine dair yayımlanmış ölçüm yok (Anthropic yalnız sandbox için %84 prompt azalması veriyor, maliyet değil).
- GitLab semantik risk sınıflandırması shipped değil; GitHub'da native yol-tabanlı reviewer yönlendirmesi olmadığı iddiası topluluk kaynaklı, GitHub dokümanından doğrulanmadı.
