# Claude Code'un kendi çoklu-ajan mekanizmalarıyla rol tabanlı "ekip" çalıştırma (durum: 2026-11-01)

Kaynak notu: Resmî dokümanlar `code.claude.com/docs` üzerinden 2026-11-01'de çekildi; dokümanlarda anılan en yeni sürüm v2.1.316 (CHANGELOG). Topluluk kaynakları "anekdot" olarak işaretlendi. Doğrulanamayan iddialar "doğrulanmamış" ile işaretlendi.

## KQ1 — Her mekanizma için: resmî tanım, sert sınırlar, uygulayıcı deneyimi

### Takeaway
Claude Code 2026 sonunda beş paralel çalışma yüzeyi sunuyor (subagent, agent view/background session, agent teams, dynamic workflows, projects) ve bunları destekleyen üç araç (worktrees, cross-session messaging, `/batch`). Resmî karşılaştırma tablosu "kim koordine eder / işçiler konuşur mu / aynı dosyaya dokunur mu" sorularıyla seçim yaptırıyor; Agent Teams hâlâ deneysel ve varsayılan kapalı, maliyeti en yüksek; subagent'lar en ucuz ama yalnız özet döndürüyor; workflows planı koda taşıyor ve en çok ölçekleniyor.

### Cited Findings

#### 1a. Custom subagents (`.claude/agents`)
- Tanım: subagent "run in its own context window with a custom system prompt, specific tool access, and independent permissions"; aynı usage limitine yazar. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Dosya yerleri ve öncelik: Managed settings (1) > `--agents` CLI (2) > `.claude/agents/` (3) > `~/.claude/agents/` (4) > plugin `agents/` (5). Dizinler rekürsif taranır; aynı `name` iki dosyada varsa yalnız biri yüklenir ("chosen by filesystem read order"), `/doctor` bunu raporlar. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Frontmatter alanları: `name` (zorunlu, ≤256 kar., `:` yok), `description` (zorunlu), `tools`, `disallowedTools`, `model` (`sonnet|opus|haiku|fable|<id>|inherit`), `permissionMode`, `maxTurns` (v2.1.246+ ile kısmi çıktı resume edilebilir), `autoCompactWindow` (100k–1M, v2.1.296+), `skills` (ilk 32 ad), `mcpServers`, `hooks`, `memory` (`user|project|local`), `background`, `omitClaudeMd` (v2.1.271+), `effort`, `isolation: worktree`, `color`, `initialPrompt`, `experimental.cacheTtl`. Tanınmayan alanlar sessizce yutulur; `claude --debug` + "does not recognize or apply" ile yakalanır (v2.1.296+). — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- `disallowedTools` tuzağı: `Bash(git push *)` gibi bir giriş "still removes the whole Bash tool". — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Description bütçesi: built-in olmayan tüm description'lar 15.000 token'ı aşarsa başlangıçta uyarı. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Nesting: alt-ajanlar kendi alt-ajanlarını açabilir, varsayılan derinlik 3 katman; `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` değiştirir, `1` nesting'i kapatır. Derinlik sınırında `Agent` aracı çekilir (fork'larda listede kalır ama hata döner). — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Eşzamanlılık: varsayılan 20 çalışan subagent; aşıldığında `Concurrent subagent limit reached`; `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (v2.1.217+); ultracode açık oturumlar muaf; oturum başına toplam sayı sınırsız. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Subagent'tan daima kaldırılan araçlar: `Agent` (derinlik sınırında), `AskUserQuestion`, `EndConversation`, `EnterPlanMode`, `ExitPlanMode`, `ScheduleWakeup`, `WaitForMcpServers`, `Workflow`. Background subagent'lar sabit bir built-in araç kümesini tutar; kaldırma sessizdir, "the same definition can resolve to different tools in foreground and background". — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Permission mode mirası: ana oturum `bypassPermissions|acceptEdits|auto` ise subagent o modda çalışır ve kendi `permissionMode`'u yok sayılır; ana oturum `plan` ise plan'da kalır; yalnız `default|dontAsk`'ta kendi modu geçerli. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- `isolation: worktree`: geçici worktree "branched by default from your default branch rather than the parent session's HEAD"; değişiklik yoksa otomatik silinir; worktree dışına çözümlenen Bash/PowerShell komutları ve ana checkout'a git yönlendiren komutlar engellenir. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents); [Worktrees docs](https://code.claude.com/docs/en/worktrees)
- Memory: `memory: project` → `.claude/agent-memory/<agent-name>/` (önerilen, versiyonlanabilir); `user` → `~/.claude/agent-memory/<name>/`; `local` → `.claude/agent-memory-local/<name>/`. `MEMORY.md`'nin ilk 200 satırı veya 25 KB'ı enjekte edilir. Auto memory kapalıysa (`autoMemoryEnabled`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY`) etkisiz. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Ne yüklenir: kendi system prompt'u, delegasyon mesajı, CLAUDE.md (Explore/Plan hariç), git status snapshot, preloaded skills, `SendMessage` varsa "sibling roster". Almadığı şeyler: "conversation history, invoked skills, files already read, your output style, or main-conversation auto memory". — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Foreground/background: ana oturumdan açılan subagent varsayılan background'da başlar; `CLAUDE_CODE_FORK_SUBAGENT=0` ile Claude sonucu bekleyebilir; `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` tüm background'ı kapatır. Sonuçlar sonraki turda "completion notification" olarak gelir. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Resume: her çağrı yeni instance; devam için `SendMessage` (`to`: agent ID), agent teams gerekmez; resume edilen ajan tam geçmişini korur ve prompt cache'i yeniden kullanır. v2.1.304 öncesinde "a subagent messaged right after finishing could forget its last work". v2.1.299 öncesinde restart sonrası ad ile gönderim reddediliyordu. Transkriptler `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`, `cleanupPeriodDays` (30) sonra silinir. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Çıktı tarama: subagent raporu Claude okumadan taranır; şüpheli etiketlere backslash eklenir ve `[harness: subagent output matched instruction-shaped pattern(s): ...]` işareti konabilir. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Maliyet: "each subagent spends tokens of its own while it runs" ve dönen sonuç ana bağlama eklenir. Best-practices: "a fresh subagent first has to gather context your conversation already had, so it can end up *slower* than doing the task where you are" ve "You get parallelism or a fresh pair of eyes out of it, but not a smarter answer". — [Best practices](https://code.claude.com/docs/en/best-practices)
- Örnek read-only reviewer tanımı resmî dokümanda: `tools: Read, Grep, Glob` ile "it's a reviewer that can't edit anything, and that limit is enforced by Claude Code rather than requested in a prompt". — [Best practices](https://code.claude.com/docs/en/best-practices)
- Anekdot (vendor blog, CloudZero, 2026-05-18): subagent'lar en düşük maliyetli katman; "Commit subagent YAML files to the repo (in `.claude/agents/`) to lock in model choices"; Opus orkestratör + Sonnet işçi önerisi. — [CloudZero](https://www.cloudzero.com/blog/claude-code-agents/) (anekdot, ürün tanıtımı içerir)

#### 1b. Agent Teams (deneysel)
- Etkinleştirme: `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` (shell veya `settings.json` `env`). Uyarı: "Agent teams are experimental and disabled by default… known limitations around session resumption, task coordination, and shutdown behavior". — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Yalnız interaktif: "Spawning teammates also requires an interactive session. In non-interactive mode with the `-p` flag, including Agent SDK sessions, Claude doesn't spawn teammates". — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Yan etki: teams açıkken Claude'un adlandırdığı her subagent teammate olarak başlar, "so teams can form even when you didn't ask for one"; kapatmak için değeri `0` yap. — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Mimari: team lead, teammates, shared task list, mailbox. Inbox: `~/.claude/teams/{team-name}/inboxes/{agent-name}.json`; team config `~/.claude/teams/{team-name}/config.json` (oturum bitince silinir); task list `~/.claude/tasks/{team-name}/` (diskte kalır, `cleanupPeriodDays`). Team adı `session-` + session ID'nin ilk 8 karakteri. Config elle yazılmaz ("your changes are overwritten"); `.claude/teams/teams.json` gibi proje düzeyinde eşdeğer yoktur. — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Task claiming "uses file locking to prevent race conditions"; bağımlı görevler otomatik unblock edilir; Task tools olmayan ajanlar yalnız mesajla koordine olur. — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Display: `in-process` (varsayılan) veya split panes (tmux ya da iTerm2 + `it2`); `teammateMode: auto|tmux|iterm2`; `--teammate-mode` bayrağı `--help`'te görünmez. Split-pane VS Code terminal, Windows Terminal, Ghostty'de desteklenmez. — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Subagent tanımı teammate olarak: `tools`, `model`, `disallowedTools`, `effort`, `autoCompactWindow` (v2.1.296+) uygulanır; in-process'te body "appended to default system prompt", split-pane'de body system prompt'un yerine geçer; `skills` alanı HİÇ uygulanmaz; `mcpServers` yalnız split-pane'de. In-process teammate'e `SendMessage` + Task tools her zaman eklenir (disallowed olsa bile). — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- İzinler: teammate lead'in permission mode'unu miras alır (`dontAsk` hariç); spawn anında teammate başına mod ayarlanamaz; permission prompt'lar lead'de görünür; `--allowedTools` split-pane teammate'e geçmez (çözüm: `claude --settings '{"permissions":{"allow":[...]}}'`); `--disallowedTools`/`--tools` split-pane'e v2.1.309+ ile geçer. — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Plan onayı: lead plan mode'daysa teammate plan'da başlar; plan hazır olunca "Claude Code approves the plan as soon as the request arrives, without the lead reviewing it" (teammate'in modu değiştirilmediyse). — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Ajanlar arası mesaj güvenliği: alıcıya mesajın başka bir Claude oturumundan geldiği söylenir; "A teammate can't approve a permission prompt or supply consent on your behalf"; auto mode classifier her mesajı iletim öncesi inceler. — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Sınırlar (resmî liste): `/resume` ve `/rewind` in-process teammate'leri geri getirmez; "Task status can lag: teammates sometimes fail to mark tasks as completed, which blocks dependent tasks"; shutdown yavaş olabilir; oturum başına tek takım; "No nested teams"; in-process teammate'ten background subagent açılamaz (`background: true` hata verir); lead sabittir. — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Worktree: "Agent teams don't isolate teammates in worktrees, so partition the work so each teammate owns a different set of files". — [Run agents in parallel](https://code.claude.com/docs/en/agents)
- Ekip boyutu: "Start with 3-5 teammates for most workflows… If you have 15 independent tasks, 3 teammates is a good starting point"; "Having 5-6 tasks per teammate keeps everyone productive". — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Maliyet: "Agent teams use approximately 7x more tokens than standard sessions when teammates run in plan mode"; "Token costs scale linearly"; in-process teammate prompt cache TTL varsayılan 5 dk (`subagentPromptCacheTtl: 1h` ile 1 saat, daha pahalı cache write). — [Costs docs](https://code.claude.com/docs/en/costs); [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- CHANGELOG düzeltmeleri (son sürümler): v2.1.311 "Fixed agent teams sessions showing an empty task list when coming back with `--resume`, `--continue`"; v2.1.309 split-pane teammate'lerin lead'in `--tools`/deny kurallarını miras almaması düzeltildi; v2.1.304 shutdown onayının tüm CLI'yi kapatması düzeltildi. — [CHANGELOG](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)
- Anekdot (topluluk rehberi, FlorianBruniaux, güncelleme 2026-08-16): Agent Teams v2.1.32'de 2026-02-05'te tanıtıldı; "Start 2-3, scale progressively", ">5 agents = coordination overhead > productivity"; her 3-4 builder'a bir read-only reviewer; tahmini token çarpanları 1.7x–2.5x (ölçüm değil tahmin); "Agent teams justified when time saved > 2x token cost increase"; tuzaklar: aynı satır düzenlemeleri, farklı bitiş süreleri, "Agents see only explicit messages, not each other's context". — [claude-code-ultimate-guide/agent-teams.md](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/guide/workflows/agent-teams.md) (anekdot)
- Anekdot (GitHub issue aynası, Claude Code 2.1.90): "Teammate does not report back. It just idles around and need also a message to continue". — [claudeissues #42514](https://claudeissues.com/issue/42514-bug-claude-code-sometimes-does-not-continue-need-a-ping-message-status-continue) (anekdot); "[BUG] Agent teams hang claude code" (2026-02-08, kapalı, race condition şüphesi). — [claudeissues #24253](https://claudeissues.com/issue/24253-bug-agent-teams-hang-claude-code) (anekdot)
- Anekdot (sistemprompt.io ve diğer bloglar): bazı rehberler "15x" çarpanı aktarır; bu rakam resmî costs sayfasında bulunamadı — **doğrulanmamış**. — [WebSearch özeti, systemprompt.io](https://systemprompt.io/guides/claude-code-agent-teams)

#### 1c. Dynamic workflows / `ultracode` (`agent()`, `parallel()`, `pipeline()`)
- Tanım: "A dynamic workflow is a JavaScript script that orchestrates many subagents at once. Claude writes the script… and a runtime executes it in the background". Tüm ücretli planlarda, API, Bedrock, Google Agent Platform, Foundry'de; Pro'da `/config`'den açılır. — [Workflows docs](https://code.claude.com/docs/en/workflows)
- Karşılaştırma tablosu: "Who decides what runs next" → Subagents/Skills: Claude; Agent teams: lead; Workflows: "The script". Ölçek: "Dozens to hundreds of agents per run". Kesinti: subagent/skill "Restarts the turn", teams "Teammates keep running", workflows "Resumable in the same session". — [Workflows docs](https://code.claude.com/docs/en/workflows)
- Tetikleme: prompt'ta `ultracode` anahtar kelimesi veya "use a workflow"; `/effort ultracode` oturum geneli (öncesi v2.1.284'te `off` çalışmıyordu); `claude --effort ultracode` ayrıca xhigh ayarlar. Keyword yalnız insan tarafından yazılan prompt'ta çalışır (`-p`, SDK, scheduled task, webhook'ta değil). — [Workflows docs](https://code.claude.com/docs/en/workflows)
- Script API: `agent(prompt, {schema, label, stallMs})`, `pipeline(list, fn)`, `parallel(tasks)`, `phase(title)`, `log()`, `args` global; `export const meta = {name, description, phases?}` ilk ifade olmalı. `agent()` durdurulursa veya kurtarılamaz API hatasında `null` döner; `pipeline()` `null`'ları korur (`.filter(Boolean)`). Schema doğrulama 5 denemede başarısızsa hata (`MAX_STRUCTURED_OUTPUT_RETRIES`). `Date.now()`, `Math.random()`, `new Date()` script içinde throw eder (determinist replay için). — [Workflows docs](https://code.claude.com/docs/en/workflows)
- Sert sınırlar: "No mid-run user input" (aşamalar arası onay için her aşamayı ayrı workflow yap); script'ten doğrudan dosya/shell erişimi yok; `import()` yok; varsayılan 16 eşzamanlı ajan (`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` 1–256, v2.1.269+); tek `parallel()`/`pipeline()`'da en çok 4.096 öğe; "1,000 agents total per run". — [Workflows docs](https://code.claude.com/docs/en/workflows)
- Maliyet uyarısı: 25'ten fazla ajan veya 1.5M projeksiyon token'da `Large workflow` uyarısı (danışma amaçlı); size guideline `small <5 / medium <10 / large <50`, varsayılan medium (Pro v2.1.271+ small). Ultracode açıkken uyarı ve concurrent subagent limiti devre dışı. — [Workflows docs](https://code.claude.com/docs/en/workflows)
- Resume: oturum içinde `/workflows` → `p`; durdurulan run'ı Claude aynı script ile relaunch eder; tamamlanmış ajanlar cache'ten döner, ilk farklı-prompt'lu ajandan itibaren hepsi yeniden çalışır; başarısız bir ajan "and so does every agent the script starts after it, even ones that completed". v2.1.305 öncesi `pipeline()/parallel()` tamamlanan ajanları gereksiz yeniden çalıştırıyordu. Oturumdan çıkılırsa run kendi kendine devam etmez; `nothing to resume` hatası yeni run gerektirir. — [Workflows docs](https://code.claude.com/docs/en/workflows); [CHANGELOG v2.1.305](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)
- Stall: çıktı kesilen ajan aynı prompt'tan yeniden başlar, en çok 5 restart; `agent stalled on all 6 attempts`; `stallMs` veya `CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS`. — [Workflows docs](https://code.claude.com/docs/en/workflows)
- Onay: Auto mode'da yalnız ilk launch; manual/acceptEdits'te her run (ya da "don't ask again for <name> in <path>"); `-p`/SDK'da prompt yok, `Workflow` veya `Workflow(<name>)` allow kuralı gerekir. — [Workflows docs](https://code.claude.com/docs/en/workflows)
- Kaydetme ve dağıtım: `.claude/workflows/` (proje) veya `~/.claude/workflows/`; plugin'de `workflows/` dizini, `/<plugin>:<meta.name>` olarak çalışır. Düzenleme için `/workflow-authoring` skill'i (v2.1.248+). — [Workflows docs](https://code.claude.com/docs/en/workflows)
- Kapatma: `disableWorkflows: true`, `CLAUDE_CODE_DISABLE_WORKFLOWS=1`, managed settings. — [Workflows docs](https://code.claude.com/docs/en/workflows)

#### 1d. Git worktrees + ayrı oturumlar + PR ile devir
- `claude --worktree <name>` / `-w`: `.claude/worktrees/<name>/`, branch `worktree-<name>`; ad verilmezse rastgele ad; en az bir commit gerekir. `.claude/worktrees/`'i `.gitignore`'a ekle. — [Worktrees docs](https://code.claude.com/docs/en/worktrees); [Common workflows](https://code.claude.com/docs/en/common-workflows)
- Base branch: `worktree.baseRef` `"fresh"` (varsayılan, remote default branch) veya `"head"`; branch adı verilemez. PR'dan dallanma: `claude --worktree "#1234"` → `.claude/worktrees/pr-1234` (GitLab MR URL v2.1.233+). — [Worktrees docs](https://code.claude.com/docs/en/worktrees)
- Temizlik: interaktif çıkışta temiz + adsız → otomatik silinir; adlı veya değişiklikli → sor; `claude --worktree <name> --resume` komutu çıkışta yazdırılır. `-p` çalıştırmalarında exit prompt yok, worktree ve lock kalır (`git worktree unlock` + `remove`). Subagent ve background-session worktree'leri `cleanupPeriodDays` sonrası, iş içermiyorsa süpürülür. — [Worktrees docs](https://code.claude.com/docs/en/worktrees)
- İzolasyon zorlaması (4 kontrol): ana checkout'a Edit/Write engeli; cwd ana checkout'a çözülen komut engeli; `git -C`, `GIT_DIR`, `cd` ile git yönlendirme engeli; parse edilemeyen komut şekli engeli ("You can't turn this check off"). Ancak `cp` veya shell redirect ile ana checkout'a yazma yakalanmaz. — [Worktrees docs](https://code.claude.com/docs/en/worktrees)
- Hook yolları worktree'yi izlemez: `${CLAUDE_PROJECT_DIR}` başlangıç kökünde kalır, worktree yolu hook input'undaki `cwd` alanında gelir. — [Worktrees docs](https://code.claude.com/docs/en/worktrees)
- Paylaşılanlar: `.git`, proje kapsamlı plugin'ler, izin onayları (ana checkout `.claude/settings.local.json`'a yazılır), worktree'de `.claude/skills|agents|commands` yoksa ana checkout'tan okunur (skills için v2.1.277+). — [Worktrees docs](https://code.claude.com/docs/en/worktrees)
- `.worktreeinclude` (`.gitignore` sözdizimi) gitignored dosyaları kopyalar; "Keep it to small files: it copies rather than links"; büyük dizinler için `worktree.symlinkDirectories`. — [Best practices](https://code.claude.com/docs/en/best-practices)
- `/batch`: "a skill that has Claude split one large change into 5 to 30 worktree-isolated subagents… Then it runs each unit in its own worktree and opens a PR for it". — [Run agents in parallel](https://code.claude.com/docs/en/agents); [Best practices](https://code.claude.com/docs/en/best-practices)
- PR bağlama: Claude `gh pr create` ile PR açınca oturum PR'a bağlanır; `claude --from-pr 1234` o PR'ın oturumlarını listeler. — [Common workflows](https://code.claude.com/docs/en/common-workflows)
- Cross-session messaging (v2.1.224+ macOS/Linux, v2.1.234+ Windows): `ListAgents` + `SendMessage`; `@session-name` mention (v2.1.232+); teslim boşta yeni tur olarak veya aktif turda tool call'lar arası; "A message is a piece of text one Claude writes to another, never the sender's conversation history or files"; `crossSessionInbound: accept|hold|refuse`; varsayılan: bypass sınıfından gelen mesaj prompting oturumda tutulur; `notify_when_idle` ile boşa düşme bildirimi (v2.1.236+, 12 saat zaman aşımı); same-machine mesaj ~1M karakter sınırı; loop koruması (tekrarlar düşürülür, en çok 50 kuyruk). `-p` worker'ı mesaj alabilir (bare mode hariç). — [Cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)
- Anekdot (resmî best-practices önerisi): "A second session is also the easiest independent reviewer you can get. One session writes the rate limiter, another reviews… and you paste the findings back into the first." — [Best practices](https://code.claude.com/docs/en/best-practices)

#### 1e. Hooks (kalite kapısı olarak) — ayrıntı KQ4'te
- Handler türleri: `command`, `http`, `mcp_tool`, `prompt`, `agent` (agent "experimental and may change"). Varsayılan timeout: 600 s (command/http/mcp_tool), 30 s (prompt), 60 s (agent). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Exit code: 0 başarı (stdout tek JSON nesneyse parse edilir), 2 blok ("The message that comes with the block is your hook's stderr"), diğerleri non-blocking. — [Hooks reference](https://code.claude.com/docs/en/hooks)

#### 1f. Plugins ve `claude plugin eval` — ayrıntı KQ5'te

### Inferences

## KQ2 — "Lead oturum planlar ve inceler, worker oturumlar worktree'de uygular ve PR açar" için önerilen kombinasyon ve yayınlanmış kurulumlar

### Takeaway
Resmî dokümanda tam bu deseni veren tek paket `/batch` (5–30 worktree-izole subagent, her biri PR açar). Deneyimli kullanıcıların yayınladığı kurulumlar ortak bir şekle oturuyor: lead = ana oturum (plan + review), worker = `claude -p` veya ayrı oturum kendi worktree'sinde, teslim = açık PR; review = kodu yazmamış taze bir oturum/subagent; merge insana bırakılır. Agent Teams bu desen için önerilmiyor (worktree izolasyonu yok, interaktif-only, resume yok).

### Cited Findings
- Resmî karar ağacı: "Do the tasks touch the same files? Isolate the work with worktrees. Subagents and sessions you run yourself can each use a separate worktree. Agent teams don't isolate teammates in worktrees". — [Run agents in parallel](https://code.claude.com/docs/en/agents)
- Resmî: unattended run için üç soru: "Can it check its own work? The test suite, a `Stop` hook, some kind of review step. What's it allowed to touch? Permission rules, `dontAsk`, the sandbox, a worktree, the one branch it may push to." — [Best practices](https://code.claude.com/docs/en/best-practices)
- Resmî headless örneği: `claude --bare -p "Migrate $file to the new logger API and commit. Reply OK or FAIL."` (`--bare` hooks, skills, plugins, MCP ve CLAUDE.md'yi atlar). — [Best practices](https://code.claude.com/docs/en/best-practices)
- Resmî reviewer deseni: `/code-review` "reviews the diff in a fresh subagent that never saw your conversation. It isn't swayed by the reasoning that produced the code"; spec'e karşı inceleme prompt'u: "use a subagent to review the rate limiter diff against SPEC.md… report gaps that affect correctness and skip style" ("Don't drop the `skip style` part"). — [Best practices](https://code.claude.com/docs/en/best-practices)
- Resmî: Agent Teams için "Start with research and review… tasks that have clear boundaries and don't require writing code". — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- **claude-coordinator** (PyPI v0.5.45, 2026-08-12, John Donaghy, Beta, FSL-1.1-MIT): board (`coord` CLI / TUI / web), makine başına `coord agent` dispatcher (port 7433), worker = "headless `claude -p` subprocess in an isolated git worktree" veya tmux'ta interaktif oturum; Work → Test → Review → Merge kapılı pipeline; `coord pr <id>` PR açar ve "auto-dispatches a review… performed by a fresh session with zero shared context, run on a different machine by default"; fix-review döngüsü en çok 3 iterasyon, sonra insan; review yalnız Test verdict `passed|skipped` ise. Sınırlar: TUI Rust ile yerel derlenir; Test verdict yoksa iş sessizce takılır; milestone gate'leri kısmen çalışır. — [claude-coordinator PyPI](https://pypi.org/project/claude-coordinator/) (topluluk)

### Gaps

## KQ4 — Hook'larla "testler geçmeden / review geçmeden bitmedi" kapıları; Stop-hook döngüleri ve iterasyon sınırı; PreToolUse deny ile rol kısıtı

### Takeaway
Resmî desen: `Stop` hook'u exit 2 ile turu bitirmeyi engeller, stderr Claude'a "neden bitmedi" olarak döner; döngü koruması `stop_hook_active` bayrağı ve **8 ardışık continuation cap** (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` ile yükseltilir; sayaç her tool call'da sıfırlanır). Teams için `TeammateIdle` ve `TaskCompleted` exit 2 ile aynı işi yapar. Rol kısıtı için PreToolUse deny her permission mode'da (bypass dahil) geçerlidir; subagent frontmatter hook'ları yalnız o subagent çalışırken çalışır ve `Stop` → `SubagentStop`'a çevrilir.

### Cited Findings
- Stop input: `stop_hook_active`, `last_assistant_message`, `background_tasks`, `session_crons`. "`stop_hook_active` field is `true` when Claude Code is already continuing as a result of a stop hook. Check this value or process the transcript to avoid blocking on a condition that will never resolve." — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Cap: "Claude Code applies an 8-consecutive-continuation cap: after stop hooks have continued the turn eight times in a row, Claude Code overrides the next block and ends the turn. The count of consecutive continuations resets each time Claude calls a tool. To raise the cap, set `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`." — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Stop karar alanları: `decision: "block"` + `reason` (zorunlu); `hookSpecificOutput.additionalContext` ("Stop hook feedback" olarak, hata bildirimi göstermeden, aynı loop korumalarıyla). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Resmî typecheck kapısı (`.claude/settings.json`): `{"hooks":{"Stop":[{"hooks":[{"type":"command","command":"pnpm tsc --noEmit 1>&2 || exit 2"}]}]}}` — "it gets the compiler errors back and keeps going until `tsc` passes". — [Best practices](https://code.claude.com/docs/en/best-practices)
- Prompt-tabanlı Stop kapısı: `{"type":"prompt","prompt":"Check if all tasks are complete. If not, respond with {\"ok\": false, \"reason\": \"what remains to be done\"}."}`; model `"impossible": true` döndürürse stop'a izin verilir. — [Hooks guide](https://code.claude.com/docs/en/hooks-guide)
- Agent-type hook: "multi-turn verification with tool access… experimental"; Read/Grep/Glob kullanıp karar verir; timeout 60 s. — [Hooks guide](https://code.claude.com/docs/en/hooks-guide); [Hooks reference](https://code.claude.com/docs/en/hooks)
- Troubleshooting "Stop hook hits the block cap": "Claude Code overrides a Stop hook after it blocks eight times in a row with no tool call from Claude in between. Your hook script needs to check whether it already triggered a continuation" (örnek: `jq -r '.stop_hook_active'` true ise `exit 0`). — [Hooks guide](https://code.claude.com/docs/en/hooks-guide)
- SubagentStop: Stop ile aynı format; `agent_id`, `agent_type`, `agent_transcript_path`, `last_assistant_message`; v2.1.271+ `SubagentHandback` kullanan subagent'ta rapor `tool_input.message`'da (PreToolUse/PostToolUse `SubagentHandback` matcher). Parent'a bağlam enjekte etmek için `PostToolUse` on `Agent`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- TeammateIdle: `teammate_name`, `team_name` (deprecated), `agent_id` (v2.1.290+); exit 2 → "the teammate receives the stderr message as feedback and continues working instead of going idle"; `{"continue": false, "stopReason"}` teammate'i tamamen durdurur. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- TaskCompleted: TaskUpdate ile ya da teammate in-progress görevle turu bitirince ateşlenir; exit 2 → "the task is not marked as completed and the stderr message is fed back"; `TaskUpdate` tetiklediyse `continue: false` yok sayılır. TaskCreated: exit 2 görevi geri alır (örnek: `[TICKET-123]` formatı zorlama). — [Hooks reference](https://code.claude.com/docs/en/hooks); [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- PreToolUse deny: `hookSpecificOutput.permissionDecision: "deny"` + `permissionDecisionReason`; çoklu hook'ta öncelik `deny > defer > ask > allow`; "a hook that returns `permissionDecision: "deny"` blocks the tool even in `bypassPermissions` mode or with `--dangerously-skip-permissions`. `PreToolUse` hooks fire before any permission-mode check". — [Hooks guide](https://code.claude.com/docs/en/hooks-guide)
- Korunan dosya örneği: `PROTECTED_PATTERNS=(".env" "package-lock.json" ".git/")` → eşleşirse stderr "Blocked: …" ve `exit 2`. — [Hooks guide](https://code.claude.com/docs/en/hooks-guide)
- Reviewer "Write yapamaz" için iki resmî yol: (a) `tools: Read, Grep, Glob` (harness zorlar); (b) subagent frontmatter PreToolUse hook (resmî `db-reader` örneği: `tools: Bash` + `validate-readonly-query.sh` ile INSERT/UPDATE/DELETE engeli, exit 2) — "the hook is a backstop". — [Best practices](https://code.claude.com/docs/en/best-practices); [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Frontmatter hook'ları: "run only while the subagent is active. `Stop` is converted to `SubagentStop`"; proje düzeyinde frontmatter hook için agent dosyasının klasörü trust edilmiş olmalı ("Trusting a parent folder doesn't count, and `-p` sessions don't count as trusted"). Settings hook'ları subagent içinde de çalışır (`agent_id`, `agent_type` ile). — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents); [Hooks reference](https://code.claude.com/docs/en/hooks)
- `if` alanı (permission rule sözdizimi, tek kural) best-effort: "use the permission system rather than a hook to enforce a hard allow or deny". — [Hooks guide](https://code.claude.com/docs/en/hooks-guide)
- Deterministik vs non-deterministik: "If something has to happen every time, make it a hook, a deny rule, or a managed setting. `CLAUDE.md` is for guidelines"; "When it's done" satırı: non-deterministik = "A request for evidence, `/goal`, `/code-review`", deterministik = "Tests, typecheck, a `Stop` hook, CI". — [Best practices](https://code.claude.com/docs/en/best-practices)
- Workflow'da "keep fixing until a check passes" deseni: "run npx tsc --noEmit and keep fixing the reported errors until the type check passes or two rounds in a row make no progress". — [Workflows docs](https://code.claude.com/docs/en/workflows)
- Anekdot (claude-verify-before-stop, dev.to, 20 Mayıs [yıl belirtilmemiş]): git'te değişiklik varsa son 5 dk içinde `.claude/state/stop-verify.log`'da `VERIFY_ACTION` + `VERIFIED` kaydı ister, yoksa exit 2; `stop_hook_active` true ise hemen exit 0; yazar "v2.1.143+ … after roughly 8 consecutive Stop-hook blocks, the turn ends… `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP=20`" der (sürüm numarası resmî dokümanda yok — v2.1.143 iddiası doğrulanmamış; cap'in varlığı resmî). Tavsiye: "design the hook so the model has enough information to comply on the next turn, not on the eighth". — [dev.to ianymu](https://dev.to/ianymu/stop-claude-code-from-lying-about-completion-a-50-line-bash-hook-1g2b); repo [ianymu/claude-verify-before-stop](https://github.com/ianymu/claude-verify-before-stop) (anekdot)
- Anekdot (GitHub issue #54360, 2026-04-28, v2.1.121): Stop hook aynı turda 5+ kez ateşlendi, `stop_hook_active` her seferinde `false` kaldı; tetikleyici araya giren system reminder'lar (`<task-notification>`, UserPromptSubmit çıktısı); sonuç token yanması ve "verified, holding" tarzı minimal yanıtlara kayma; workaround 60 s sentinel rate-limit. Bot tarafından 2026-05-30 "not planned" kapatıldı, maintainer yanıtı yok. — [anthropics/claude-code #54360](https://github.com/anthropics/claude-code/issues/54360) (anekdot; 8'lik cap'in bu tür döngüleri sonradan sınırlaması muhtemel, doğrulanmadı)
- Anekdot (topluluk rehberi): görev başına "maximum of 8 retry attempts" ve ajan başına token cap (%85'te auto-pause) öneriliyor. — [claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/guide/workflows/agent-teams.md) (anekdot)

### Inferences
- Güvenilir kapı reçetesi: komut-tipi Stop hook (test/typecheck, stderr'e yönlendir, `|| exit 2`), `stop_hook_active` kontrolü, cap'i bilinçli bırak (8) veya `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` ile artır; "review geçmeden bitmedi" için prompt/agent-tipi Stop hook ya da worker tarafında `SubagentStop`/`TaskCompleted`.
- Worktree'de çalışan worker için kapı script'i `cwd`'yi okumalı; aksi halde `${CLAUDE_PROJECT_DIR}` ana checkout'u test eder.
- Rol kısıtının en sağlam katmanı `tools` allowlist'i; PreToolUse deny ise "Bash'i tutup yalnız bazı komutları engelle" gibi ince kontrol için backstop.

### Gaps
- 8'lik cap'in hangi sürümde eklendiği resmî CHANGELOG'da (ilk 100k karakter) bulunamadı.
- #54360'daki "system reminder araya girince `stop_hook_active` false kalıyor" davranışının güncel sürümde düzeltildiğine dair kayıt yok.

## KQ5 — Plugin paketleme: ne gönderilebilir / gönderilemez; `claude plugin eval` suite'leri ve CI

### Takeaway
Plugin'ler skill, command, agent, hooks (`hooks/hooks.json`), MCP (`.mcp.json`), LSP, output style, theme, workflow, monitor, `bin/` ve kısıtlı `settings.json` taşır; **plugin agent'ları `permissionMode`, `hooks`, `mcpServers`, `initialPrompt` alanlarını yok sayar**, plugin kökündeki `CLAUDE.md` yüklenmez, plugin settings'te yalnız `agent` ve `subagentStatusLine` geçerlidir. `claude plugin eval` (v2.1.269+) her case'i plugin'li ve plugin'siz 3'er kez izole `-p` oturumunda koşturur, 6 grader tipi vardır, `--threshold` altı case exit 1 verir; CI reçetesi `--json --trust-plugin --model/--judge-model pin --no-publish --max-cost-usd`.

### Cited Findings
- Plugin agent frontmatter: "Supported fields: `name`, `description`, `model`, `effort`, `maxTurns`, `autoCompactWindow`, `tools`, `disallowedTools`, `skills`, `memory`, `background`, `omitClaudeMd`, `isolation`, `color`, and the `cacheTtl` key of `experimental`… Ignored fields: `permissionMode`, `hooks`, `mcpServers`, and `initialPrompt`. An agent file can't add hooks or MCP servers on its own, so add those as plugin hooks and MCP servers instead". Parse edilemeyen frontmatter'da ajan yine yüklenir, açıklaması `Agent from my-plugin plugin` olur. — [Plugin components](https://code.claude.com/docs/en/plugins/components)
- Plugin agent adı `<plugin>:<name>`; alt klasörler ada eklenir (`my-plugin:review:security`); `@agent-my-plugin:security-reviewer` ile çağrılır; hook matcher'larında `^my-plugin:reviewer$` anchor önerilir. — [Plugin components](https://code.claude.com/docs/en/plugins/components); [Hooks reference](https://code.claude.com/docs/en/hooks)
- CLAUDE.md: "A `CLAUDE.md` at the plugin root isn't loaded as context, and `claude plugin validate` warns when it finds one. To include instructions that load into Claude's context, put them in a skill." — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- Settings: "Only `agent` and `subagentStatusLine` take effect; other keys are dropped at load"; `agent` ile oturumun ana thread'i plugin'in ajanı olarak çalıştırılabilir. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference); [Plugin components](https://code.claude.com/docs/en/plugins/components)
- Hooks: `hooks/hooks.json` üst düzey `"hooks"` sarmalayıcı ister; "A plugin's hooks don't wait for one of the plugin's skills or commands to be used… they fire on their events from then on"; aynı adlı iki plugin'den yalnız biri hook kaydeder; `WorktreeCreate` plugin hook'u `--worktree --tmux` ile çalışmaz (v2.1.300 öncesi `--worktree` ile de çalışmıyordu). — [Plugin components](https://code.claude.com/docs/en/plugins/components); [Hooks reference](https://code.claude.com/docs/en/hooks)
- Diğer sınırlar: `bin/` olan plugin claude.ai/Cowork'e kurulamaz; monitor'lar `-p`'de başlamaz ve `${user_config.*}` alamaz; shell-form hook komutlarında `${user_config.*}` reddedilir (exec-form `args` veya `CLAUDE_PLUGIN_OPTION_<KEY>`); `${CLAUDE_PLUGIN_ROOT}` güncellemede değişir (durum `${CLAUDE_PLUGIN_DATA}`'ya). — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- Workflow dağıtımı: `workflows/` dizini, `/<plugin>:<meta.name>`. — [Workflows docs](https://code.claude.com/docs/en/workflows)
- `claude plugin validate`: `--strict` ile uyarılar hata olur (CI için); MCP girişlerini de denetler (v2.1.281+); agents dizinini denetler (v2.1.233+). — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- **Eval gereksinimleri**: Claude Code v2.1.269+, Git 2.31+ (varsa), manifest'li plugin dizini; "Every eval run and every judge grader is a real model call on your account". — [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
- Çalışma: her run "a fresh, isolated non-interactive session with only your plugin loaded"; varsayılan 3 run/case; case skoru = run'ların ortalaması; "A case passes when its score meets the `--threshold`, `1.0` by default"; with-arm / without-arm (no-plugin baseline), `Δ` raporlanır ama exit code'u etkilemez. — [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
- Suite yapısı: `evals/<case>/prompt.md` (frontmatter: `max_turns` varsayılan 10/üst 200, `timeout_seconds` 300/3600, `model`, `tags`, `allowed_tools`), isteğe bağlı `case.yaml` (`schema_version: "1.1"`, `name`, `execution:`, `context.scaffold_script`, `context.history_file`), `graders/<name>.md`; `claude plugin eval init` (interaktif) veya `init --bare <name>`. — [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
- Grader tipleri (6): `regex`, `tool_used` (`tool`, `input_match`, `min`, `max`; `min:0 max:0` = asla çağrılmadı), `tool_order` (`before`/`after`), `file_exists` (yalnız run'da oluşturulan dosyalar) — maliyetsiz; `llm`, `baseline` — judge çağrısı. "There are no custom-code graders." `tool_used: Skill` grader'ları iki kollu run'da `scored: false` ("plugin-fired indicator"). — [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
- Ajan testi: "a case that lists `Agent` in `allowed_tools` can dispatch one of your plugin's agents by its namespaced name, such as `my-plugin:code-reviewer`". — [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
- Araç izinleri: varsayılan yalnız read-only (`Read, Glob, Grep, NotebookRead, Skill, AskUserQuestion, Agent, TodoWrite`, Task tools); `Bash/Write/Edit/WebFetch/WebSearch` için `--allow-tools`; Bash OS sandbox altında, sandbox backend yoksa run reddedilir (native Windows → WSL2; Linux `bubblewrap`+`socat`). MCP mock'ları `evals/mocks/<server>/<tool>.md`. — [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
- CI reçetesi: `--json results.json --threshold 0.8 --trust-plugin --model <pin> --judge-model <pin> --no-publish --max-cost-usd 20`; exit 0 geçti, 1 threshold altı/yükleme hatası/trust yok, 2 kısmi (`--max-cost-usd` aşıldı, `partial: true`), 143 CI timeout. "`init` in CI… run `claude plugin eval init --bare <name>`". Maliyet önerisi: hızlı suite'lerde yalnız judge'sız grader'lar, `--ablation none`. — [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
- Çıktı: `results/<timestamp>/aggregate-result.json` + kendi kendine yeten `report.html`; skill-creator plugin'inin `evals/evals.json` formatı ile uyumsuz ("neither tool reads the other's case files"). — [Plugin evals](https://code.claude.com/docs/en/plugin-evals)

### Inferences
- Rol tabanlı ekip plugin'inde reviewer'ın "Write yapamaz" kuralı plugin agent frontmatter `hooks`'u ile taşınamaz; ya `tools` allowlist'i ile, ya plugin düzeyinde `hooks/hooks.json` PreToolUse (matcher `^my-plugin:reviewer$` için `SubagentStart`/`SubagentStop`, PreToolUse'da `agent_type` alanı okunarak) ile zorlanmalı.
- Plugin eval, bir "ekip" plugin'inin yalnız tekil davranışlarını (doğru skill tetiklendi mi, reviewer Edit çağırmadı mı — `tool_used: Edit, min:0,max:0`) ölçebilir; mid-run insan onayı ve gerçek PR açma `-p` + sandbox kısıtı nedeniyle mock'lanmalıdır.

### Gaps
- Agent Teams'i (interaktif-only) `claude plugin eval` ile test etmek mümkün görünmüyor; dokümanda açık ifade yok.
- Eval'in `isolation: worktree` ajanları veya `Workflow` aracını desteklediğine dair ifade bulunamadı.

## KQ6 — Subagent bağlamı (sıfır geçmiş, yalnız özet), fork subagent'lar, output style / memory yayılmaması: bilinen tuzaklar

### Takeaway
Non-fork subagent yalnız delegasyon mesajını, CLAUDE.md'yi, git status'u ve preloaded skill'leri alır; output style, okunmuş dosyalar, çağrılmış skill'ler ve ana auto memory gelmez; geri yalnız özet döner ve harness tarafından taranır. Fork tam geçmişi ve aynı araç havuzunu miras alır (ucuz cache), ama `model`/`effort` parametrelerini yok sayar, fork'tan fork açılamaz ve fork modu açıkken Claude interaktif oturumda subagent'ı bekleyemez.

### Cited Findings
- Yüklenmeyenler: "It does **not** receive conversation history, invoked skills, files already read, your output style, or main-conversation auto memory. Context window size follows the subagent's own model." — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Explore ve Plan built-in'leri CLAUDE.md ve git status'suz başlar; Explore agent ID döndürmez (resume edilemez). — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- `omitClaudeMd: true` (v2.1.271+) CLAUDE.md'yi atlar; managed policy dosyaları yine yüklenir. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Teammate'lere `skills` frontmatter alanı uygulanmaz; split-pane teammate body'yi system prompt yerine koyar, in-process body'yi ekler (aynı tanım iki modda farklı davranır). — [Agent teams docs](https://code.claude.com/docs/en/agent-teams)
- Dönüş yalnız özet: "The subagent reads files in its own context window and reports a summary"; raporlar "scanned before Claude reads them… Suspicious tags get a backslash inserted" (`[harness: subagent output matched instruction-shaped pattern(s): ...]`). Auto mode'da classifier final raporu teslimden önce inceler. — [Common workflows](https://code.claude.com/docs/en/common-workflows); [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Fork: "inherits the entire conversation so far… This drops the input isolation"; tablo: Context = Full history; System prompt/tools = Same as main; Model = Same as main; Prompt cache = Shared ("a fork costs less than a fresh subagent"). `isolation: "worktree"` fork'a verilebilir; "A fork can't spawn further forks"; fork'lar per-invocation `model` ve `effort`'u yok sayar; derinlik sınırında `Agent` aracı listede kalır ama hata döner. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Fork modu: v2.1.302'den itibaren `-p`/SDK'da da varsayılan açık (`CLAUDE_CODE_FORK_SUBAGENT=0` kapatır); interaktif terminalde v2.1.232'den; "While fork mode is on, Claude also can't wait for a subagent… in interactive terminal, VS Code, or desktop sessions". `/subtask` ile elle fork; agent view kapalıysa `/fork` fork subagent başlatır, açıksa `/fork` tüm oturumu yeni background session'a kopyalar. v2.1.307: birlikte başlatılan fork'lara hangisinin kendisi olduğu söyleniyor. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents); [Run agents in parallel](https://code.claude.com/docs/en/agents); [CHANGELOG](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)
- Memory yayılmaması: `memory:` frontmatter'ı yalnız o ajanın kendi `agent-memory/<name>/` dizinidir; ana oturumun auto memory'si subagent'a gelmez; auto memory kapalıysa ajan memory'si de etkisizdir. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Araç filtresi sürprizi: background subagent'ta sabit araç kümesi, foreground'da tanımın tamamı — "Removal is silent". — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Worktree subagent'ı CLAUDE.md'yi ana konuşmadan alır, worktree kökündekini okumaz. — [Worktrees docs](https://code.claude.com/docs/en/worktrees)
- Thinking: subagent'lar v2.1.198+ ile ana oturumun extended thinking'ini miras alır ("Before that, thinking was always off"). — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Model fallback: `availableModels` allowlist dışı model aile içindeki en yeni izinli sürümle değiştirilir; `⚠ This agent switched to <model>` uyarısı. — [Sub-agents docs](https://code.claude.com/docs/en/sub-agents)
- Resmî "What you can stop doing": "Use subagents to protect your context window — Running out of context is rarely the problem anymore"; "Delegate to a subagent for a better answer — Handing the same task to a subagent doesn't make the answer any better. A fresh reviewer does help". — [Best practices](https://code.claude.com/docs/en/best-practices)
- Anekdot (topluluk rehberi): "Context isolation: Agents see only explicit messages, not each other's context". — [claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/guide/workflows/agent-teams.md) (anekdot)
- Anekdot (CloudZero): `/clear` ile bağlam temizliği "reduces per-message token cost by an estimated 30–50%" (tahmin). — [CloudZero](https://www.cloudzero.com/blog/claude-code-agents/) (anekdot)

### Inferences
- Rol tanımındaki "stil" (output style) subagent'a geçmediği için, reviewer çıktı formatı ajanın body'sine yazılmalı.
- Lead'in plan bağlamını worker'a taşımanın güvenilir yolları: spawn prompt'una açık yazmak, `SPEC.md` gibi dosyaya işaret etmek, ya da fork kullanmak (fakat fork aynı model/araçlarla sınırlı ve worktree dışında ana checkout'a yazar).
- Aynı ajan tanımının foreground/background ve in-process/split-pane'de farklı çözümlenmesi, "ekip" tanımlarını tek modda test edip o moda sabitlemeyi gerektirir.

### Gaps
- Output style'ın teammate'lere (agent teams) yayılıp yayılmadığı dokümanda açıkça yazılmıyor.
- Fork'un `memory:` dizinini kullanıp kullanmadığı belirtilmemiş.
- Topluluktan "subagent özeti kritik ayrıntıyı düşürdü" tipi ölçülmüş vaka raporu bulunamadı; yalnız resmî uyarılar var.
