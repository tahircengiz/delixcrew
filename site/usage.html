How to use

delixCrew is a Claude Code plugin. Once it is installed, you start work with a single request. The lead proposes each next step and waits for your decision at two gates. This page covers installation, the first job, the commands, the files it creates in your project and the known limits. How the system works is on the What it is page.

Requirements

Three required tools, two optional

ToolNeededWhy
Claude CoderequiredA version with plugin marketplaces. Tested with 2.1.309; older versions are not tested.
python3requiredThe hooks are Python scripts (tested with 3.9) and block on failure. Without python3 on PATH, Write, Edit and Bash are blocked in every session.
gitrequiredImplementer sessions work on card branches in separate worktrees.
ghoptionalThe GitHub CLI, signed in, to open and read PRs. Without it the commits stay on the card branch and the report says **PR:** none.
gitleaksoptionalA secret scan before every implementer commit. Without it a note goes to .delix/warnings.log. Required for sending feedback.

Install

Two commands to install, two to update

Installation works in the desktop app and in the terminal; no --plugin-dir is needed. No GitHub SSH key is needed either: marketplace add tries SSH and falls back to HTTPS.

  1. Add the marketplace

    claude plugin marketplace add tahircengiz/delixcrew

  2. Install the plugin

    claude plugin install delixcrew@delixcrew

    From a local clone: first claude plugin marketplace add /path/to/delix, then the same install command.

Update

claude plugin marketplace update delixcrew
claude plugin update delixcrew@delixcrew

Then restart Claude. An install copies the plugin into Claude's cache, one folder per version, so an update arrives only when the version in plugin.json changes; git pull alone is not enough.

Trying a local change

To read a folder in place without a version bump: claude --plugin-dir /path/to/delix. If you installed it before 0.4.0 under the name delix, the migration steps are in CHANGELOG 0.4.0.

First job

From a request to a merge, step by step

You type the commands in the lead session, in the project's main checkout. The lead proposes the next step at the end of each one; the order is below. Amber steps are your decisions.

  1. /delixcrew:start <request>

    The lead reads CLAUDE.md, STATUS.md and docs/delix/. It proposes a size (S/M/L, process weight) and a tier (1/2/3, risk) and sets up docs/delix/. For S a single card is written. For well-described work of size S or M and at most Tier 2, it proposes a single session plus /delixcrew:verify instead of the full flow.

  2. /delixcrew:spec · size M and L

    The grill asks one question at a time and adds its recommendation to each. The result is docs/delix/SPEC.md, with requirements in SHALL and WHEN/THEN form. The architect reviews the spec, and security too at Tier 3. For UI work the spec links DESIGN.md or the repo's token file, and produces DESIGN.md when neither exists.

  3. Gate 1 · spec approval

    You approve the spec (the card, for S). For Tier 3 cards you also say an explicit "yes" in chat; the lead writes the **🔐 Approved:** <date> <who> line into the card header and commits it to main.

  4. /delixcrew:dispatch

    The architect writes the cards and the wave plan and checks that Files lists do not overlap. Each card gets a dispatch prompt (docs/delix/tasks/T<nnn>.dispatch.md) and you are told how to open its session. At most 3 cards run at once. Tier 1–2 cards open headless with claude -p in a terminal, Tier 3 cards in an interactive session.

  5. /delixcrew:implement <card> · implementer session

    The dispatch prompt calls this skill; you do not type it. The implementer writes a failing test first, touches only the card's Files list, runs the verification command, opens a PR and fills in .delix/report.md. The Stop hook does not end the turn until the tests pass.

  6. /delixcrew:review <card>

    First the deterministic gates: test result, CI, gitleaks. Then qa with zero context, plus security at Tier 2 and above. Only serious findings (P0/P1) open a fix round; at most 3 rounds, then the decision is yours.

  7. Gate 2 · merge

    You merge the PR; the lead never runs gh pr merge. The card becomes accepted and the next wave opens.

  8. /delixcrew:close

    Once every card is merged: STATUS and CHANGELOG, per-card cost and round metrics, a spec-to-code drift check and worktree cleanup. Lessons learned go to CLAUDE.md or memory only with your approval.

Shortcut: /delixcrew:verify <branch|commit|dir>. It only verifies work done without a card. In order it runs gitleaks, the local tests, a remote isolated unit test (when delix.json has a verify block) and, on request, the full suite with --full. Then qa (plus security at Tier 2 and above) reviews in a single pass; there are no fix rounds. The result is written as ACCEPT or FIX to a docs/delix/verifications/<date>-<name>.md report.

Project files

What delixCrew creates in your project

The shared memory is in files: docs/delix/ on the main branch, .delix/ in each implementer worktree.

On the main branch · docs/delix/

  • delix.json: test command, protected paths, test paths, parallel card limit, the verify block
  • SPEC.md: the approved tech spec
  • tasks/T<nnn>-<slug>.md: cards and dispatch prompts
  • STATE.json: card states, waves, verifications records
  • verifications/<date>-<name>.md: verify reports
  • BOARD.md: generated only on request, in .gitignore

In the implementer worktree · .delix/

  • card: activates the hooks; must be local, not tracked by git
  • report.md: DONE, DONE_WITH_CONCERNS, NEEDS_CONTEXT or BLOCKED
  • test-result.txt: the Stop hook's test output
  • evidence/: verification evidence

Feedback

Reporting a plugin fault: off by default, you send

When a hook rejects correct work, a skill step cannot be followed as written, or you work around a limit by hand, delixCrew can keep a draft of it. It never sends anything on its own. Drafts live in ~/.claude/delixcrew/feedback/, not in your project repo.

  1. Turn it on in your own terminal

    python3 <plugin dir>/scripts/feedback.py enable --terms acme,example-corp

    For a marketplace install the script is at ~/.claude/plugins/cache/delixcrew/delixcrew/<version>/scripts/feedback.py. --terms adds your own words to redact (customer names, codenames). status shows the state, disable turns it off.

  2. A draft is created

    You say /delixcrew:feedback note in chat, or close and review add a draft when one of the three events above happened. A repeated finding raises the draft's count instead of adding a new one.

  3. See the full text

    /delixcrew:feedback review shows each draft exactly as it would be published: repo, label, title, body, a VERDICT: and a HASH: line.

  4. Approve by id in chat

    Reply with the id of the draft you want to send: yes F003 (or evet F003). A bare "yes", "send all" or an "approved" in a file is not consent. Claude then gives you one command.

  5. Send from your own terminal

    python3 <plugin dir>/scripts/feedback.py send F003 --confirm <hash>

    It prints the text once more and waits for you to type SEND <hash>. If the text changed since the preview, it stops.

The issue is public and opened with your GitHub account. Sending needs gitleaks and a signed-in gh. A draft with a secret is blocked, never redacted and sent. GitHub does not let an author delete an issue; to have one removed, use private reporting. What gets redacted is on the What it is page.

Remaining risk

The hooks close the known send paths, not all of them. For a stronger guard you can add this to your own settings.json; delixCrew does not change your settings:

{ "permissions": { "deny": ["Bash(gh issue create:*)", "Bash(gh api:*)"] } }

delix-board

An optional live board

delix-board is a separate, read-only mod in the same marketplace. It shows the board, long runs, card details and metrics live, puts a band above the prompt and shows a toast when a run ends. delixCrew does not need it to work, and it draws nothing in headless sessions.

claude plugin install delix-board@delixcrew

Limits and troubleshooting

What you should know

Known limits

  • The hooks load in every session where the plugin is installed. The implementer rules run only when cwd/.delix/card exists, the reviewer rules only when agent_type is delixcrew:*.
  • write_gate sees only the Write, Edit, MultiEdit and NotebookEdit tools, not files written through Bash. That is why a change to the card, docs/delix/** or an unapproved protected path in the diff counts as a finding in the qa review.
  • Plugin agents ignore the permissionMode, hooks and mcpServers fields; the constraint lives in the tools list and hooks/hooks.json.
  • Experimental Agent Teams are not used. The plugin has no monitor.

Troubleshooting

  • If you see delixcrew: python3 not found on PATH, install Python 3 or disable the plugin: claude plugin disable delixcrew@delixcrew.
  • No update arriving: the installed copy refreshes only when the version changes. Run marketplace update, plugin update and restart.
  • No PR opened: check that gh is installed and signed in. Without a remote the commits stay on the card branch.
  • Found a fault in the plugin itself? Use the feedback flow or open an issue on GitHub by hand.
